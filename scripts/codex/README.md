# The Codex test harness

A real Codex CLI, pinned and checksum-verified, driven against a development build of backsight inside a container, with a deterministic fake model and a scratch memory server. Nothing touches the host's `~/.codex` or backsight: `CODEX_HOME` and `BACKSIGHT_HOME` live in the container and are gone when it stops. It needs Docker and Go; it costs nothing (no model account, Hindsight's mock LLM).

```sh
scripts/codex/run.sh                      # record the fixtures (record.sh), into a new directory it prints
OUT=/some/dir scripts/codex/run.sh        # the same, into /some/dir
HARNESS_CMD=bash scripts/codex/run.sh     # a shell in the prepared container instead
NO_SERVER=1 scripts/codex/run.sh          # no memory server: the hooks run with the server unreachable
```

`run.sh [api port]` builds backsight, the fake model and the probe MCP server (static, so the image needs no Go), builds the image if missing, starts the memory stack the way `scripts/sandbox.sh` does (Compose project `bs-codex`, `bs-codex-s<n>` under `BACKSIGHT_CI_SLOT=<n>` so slots run side by side, or `CODEX_PROJECT`; never `backsight`; API port 28800 + slot × 10 from `scripts/ports.sh`), then runs the container on an internal Docker network (no route out) that only the server joins besides it: the container reaches the server by its service name, nothing on the internet and none of the host's own ports, so a recording runs offline. Hindsight keeps its Compose network, which it needs to fetch its models at its first start. Without a server (`NO_SERVER=1`) the container has no network at all. `CODEXIFY=0` keeps backsight's generated tree as is. `KEEP=1` leaves the stack and the work directory.

## The pieces

| File | What it is |
|---|---|
| `Dockerfile` | Debian (pinned digest), the official Codex 0.167.0 release assets for Linux musl x86_64 (the CLI and its code-mode host), their sha256 checked, and tmux, jq, zstd, sqlite3. backsight is not in the image: `run.sh` mounts the build read-only. |
| `prepare.sh` | In the container: a throwaway backsight home (a client of the scratch server), backsight's plugin generated by `backsight client install` (a stand-in `claude` CLI, `fake-claude.sh`, answers its checks), then adapted for Codex (`codexify.sh`, `CODEXIFY=0` keeps it as generated), installed with `codex plugin marketplace add` and `codex plugin add backsight@backsight`; the fake model started and Codex pointed at it; recording hooks on every event; the probe MCP server registered. |
| `fakeresponses/` | The fake Responses API. It logs every request whole (credentials redacted) and plays the script carried by the conversation: `<<fake [ {"call": "<tool>", "args": {…}}, {"say": "<text>"} ]>>` in a user message, one step per answered tool call, so it keeps no state. A tool is named as the model sees it or by its suffix (`memory_search` finds `mcp__backsight` / `memory_search`); `{{last:<key>}}` in args takes a value from the last tool output (a spawned agent's id). With no script it answers `ok`; compaction requests get a summary; a structured-output request (Codex's memory extraction) gets a JSON object filling its schema; Codex's memory consolidation agent writes the files Codex checks, through its code-mode `exec` tool. |
| `probemcp/` | A stdio MCP server with one tool per annotation set (`readonly`, `closed`, `plain`, `destructive`); it logs each call's `_meta` and its own environment. |
| `tap.sh` | Replaces the backsight shim in the container: it runs the real binary and records each hook's stdin, stdout, exit code and environment, the MCP server's whole JSON-RPC traffic, and the arguments of any other run (a hook started with none). With `/tmp/bs-hints` present it adds `destructiveHint: false` and `openWorldHint: false` to `memory_store` and `memory_credit` in the server's `tools/list` answer. |
| `probe.sh`, `probe-hooks.json` | A user-level hook on every Codex event that saves the payload and answers what `/tmp/probe/<event>.{stdout,stderr,rc}` hold, to try the outputs Codex accepts. |
| `record.sh`, `collect.sh` | The recording: hook trust through Codex's own review screen (tmux), an interactive session (tools, an approval prompt, a subagent, a compaction), resume, fork, `/clear`, hook outputs, tool approvals in `codex exec`, MCP process sharing, rollout compression; then the fixtures sorted and scrubbed. |
| `checks.sh` | Hook trust, approvals and identity as fixtures, from the tree as generated (`CODEXIFY=0 HARNESS_CMD=/opt/harness/checks.sh scripts/codex/run.sh`): the ignored `args`, one plugin then two (the hooks alone) under a replaced binary, a changed skill and a bumped version, backsight's server with `destructiveHint`/`openWorldHint` false (added by `tap.sh` when `/tmp/bs-hints` exists) in the TUI and in `codex exec`, `_meta.sessionId` against the hooks' `session_id` after `/clear`, resume and fork, what plugin removal leaves, and that the container is offline. One line per step in `fixtures/checks/results.txt`. |
| `lib.sh` | The tmux helpers the scenarios share. |
| `roundtrip.sh` | The install round trip on a throwaway `CODEX_HOME` (`HARNESS_CMD=/opt/harness/roundtrip.sh`): setup with Codex alone, a session with the hooks trusted in the TUI, an update (`backsight-next`, built by `run.sh` under another version), `setup --undo`, uninstall, then install, trust, memories off, uninstall; `config.toml` compared with its start after each. |
| `server-name.sh` | The memory server named `backsight` (`HARNESS_CMD=/opt/harness/server-name.sh`), with the plugins `client install --codex` generates: what `codex mcp list` and the model see, the PostToolUse `tool_name`s, `codex exec` running the memory tools with no approval, and the name clash (`memory` none, `backsight` refused). |
| `rename-server-fixtures.sh` | Rewrites the server's name `memory` to `backsight` in the recorded fixtures (see their README). |
| `memories.sh <v2\|v1\|dual>` | Codex's own memories on disk: turns the feature on (v2, the default for a fresh profile; v1; v1 with dual write), makes three interactive sessions, ages them in Codex's state database past the one-hour idle floor and the six-hour pause between consolidations, then starts one more session, which runs the extraction and the consolidation against the fake model. Run it with `HARNESS_CMD="/opt/harness/memories.sh v2" NO_SERVER=1 scripts/codex/run.sh`; what Codex wrote lands in `fixtures/memories/<variant>/`. |

The recorded fixtures for Codex 0.167.0 are in `internal/testdata/codex/0.167.0/` (see its README).

## Notes

- Codex's own sandbox is off in the container (`sandbox_mode = "danger-full-access"` in its throwaway config): its bubblewrap cannot create a user namespace under Docker, so every shell command would fail. The container is the isolation.
- Hook trust: the recording trusts the hooks through Codex's review screen, as a user does; a trust bypass flag is never used.
- The standalone Codex binary needs `--no-daemon` for its interactive mode (the packaged CLI runs a background server instead).
- To update Codex: change `CODEX_VERSION` and `CODEX_SHA256` in the Dockerfile (the asset's digest from `gh release view rust-v<version> -R openai/codex --json assets`), record again, and compare the fixtures.
