**Pre-release.** Linux amd64 is tested; the Linux arm64, macOS and Windows binaries are built but not tested.

Update from any earlier v0.1 with `backsight update apply`: it takes a verified backup first and rolls back if a step fails. Then restart Claude Code (or run `/reload-plugins`). New install: see below.

## What changed

**Following the import of past sessions**
- `backsight retain backfill` now prints a line on stderr after each session it sends (`3/42  sent  <session>  spent …`) and when it waits for the server. With `--json` each line is a JSON progress event; stdout still holds the one result.
- New `backsight retain backfill --status`: how far the import is (sessions done and left, spend against the cap), whether a backfill is sending right now, and how to resume a paused one. It reads this machine's state only, so it answers at once, even with the server down.
- The agent guide explains how a coding agent follows the import after setup, or finishes it in one go instead of three sessions every 15 minutes.

## Install

```sh
curl -fsSL https://raw.githubusercontent.com/Barben360/backsight/main/scripts/install.sh | sh
backsight setup
```

Requirements as for v0.1.4-m5: Linux amd64, Docker with Compose v2 usable without `sudo`, Claude Code 2.1.309 or newer, an LLM provider key, about 6 GB of free disk.

## Known limits

- Tested on Linux amd64 only.
- The spend a progress line shows is measured before that session is sent; the last sessions' extraction is counted when the import ends.
- A remote server's banks are renamed on its host; its clients keep the old name and reach the bank through the alias.
- The new project rule is applied to subagent reports only; on the main conversation it is measured but not applied yet.
- Project families stay off by default: a replay on real prompts showed no change yet.
- A purge again costs a little LLM work on the server (consolidation); with the `claude-code` provider or a remote server it waits for `backsight retain purge-again --allow-subscription`.
