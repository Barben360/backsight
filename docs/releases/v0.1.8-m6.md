**Pre-release.** Linux amd64 is tested; the Linux arm64, macOS and Windows binaries are built but not tested.

Update from any earlier v0.1 with `backsight update apply`: it takes a verified backup first and rolls back if a step fails. Then restart Claude Code (or run `/reload-plugins`). New install: see below. No migration and no server change: the new tool, texts and hooks reach Claude through the regenerated plugin.

## What changed

**One memory for all your PCs**
- `backsight server expose --private <address>` opens your server to your other PCs, on a private address of this machine, and hands out the connection token they join with. A tailnet address (Tailscale) keeps the API key encrypted; a LAN address carries it in clear, so the command asks you to confirm it. `--loopback` closes the server again.
- `backsight server token --out <file>` writes the token again. It holds the API key, so it goes only to a terminal or to a file only you can read. `--rotate` gives the server a new key (a lost laptop): every token handed out before stops working, and your other PCs join again with the new one.
- `backsight connect --token-file <file>` makes another PC use that memory: it checks the server first, shows what it will change and asks before writing, then wires Claude Code as setup does. The token is read from a file or from stdin, never from the command line. A PC that ran its own server can join too: its server is backed up, the archive verified, then stopped, and `backsight connect --undo` takes it back. `--plan` shows everything first and changes nothing.
- On a PC that joined another's server, the commands that manage the server refuse and name the host and the command to run there. `backsight doctor` says when the server has not answered for a while, when a different server answers at its address (sends then wait until you connect again), and when the two machines run different versions.
- `backsight setup --role server` sets up a machine that only holds the memory, a home server or a NAS for example, without Claude Code.
- A session continued on two PCs is sent from both instead of being set aside; the part they share may be stored twice.
- After a reboot, a server exposed on an address that appears late (Tailscale, DHCP) is started again by the 15-minute job and at the next session start.

**Which memories Claude used**
- Each memory shown to Claude now carries its project and a short id, the first 8 characters of its id: `[billing · 0b4c2a52]`.
- New memory tool `memory_credit`: once Claude knows what informed its answer, it names those memories, or says none helped. The tool hands back the line it prints: `🧠 From memory (billing · 0b4c2a52) — …`. It accepts only memories shown in the session. The instruction set moves to v7.
- When a turn showed memories and Claude ends it without saying which it used, it is asked once, with the memories listed, then finishes. `feedback.stop_check = "cited"` asks only when Claude cited a memory or searched the memory itself; `"off"` never asks.
- backsight keeps a local record of what was shown and what was used: ids and counts only, never the text of a memory, a prompt or a reply. Every 15 minutes it settles into counts per memory: used, a miss when it was near the top and not used, or unknown when Claude never said.
- `backsight feedback log --id <id>` shows one memory's timeline: each time it was shown, where and at which rank, each time Claude used it, and its counts; `--session <id>` shows a whole session. `backsight feedback rebuild` recomputes the counts from the record.
- `backsight stats` gains two lines: `Credits` (how turns ended and what Claude reported) and `Ledger` (what settled). `backsight doctor` checks that the record can be written and that it settles.
- New `[feedback]` settings in `config.toml`, none needed: `enabled`, `stop_check`, `confident_rank`, `miss_half_life_days`, `credit_half_life_days`. `enabled = false` records nothing, does not offer `memory_credit`, and has Claude cite memories as before. backsight never writes this section; an older backsight refuses a `config.toml` that has it, so remove it before installing an older version.
- These counts do not change which memories are recalled yet.

**Look**
- The session's first line is shorter, `🧠 backsight · 🗂️ <project>`, with the word backsight in rosewood; `NO_COLOR=1` turns the color off. backsight has a logo, and the README says why it exists and lists everything it adds to Claude.

## Install

```sh
curl -fsSL https://raw.githubusercontent.com/Barben360/backsight/main/scripts/install.sh | sh
backsight setup
```

Requirements as for v0.1.7-m5: Linux amd64, Docker with Compose v2 usable without `sudo`, Claude Code 2.1.309 or newer, an LLM provider key, about 6 GB of free disk. To join the memory of a PC already set up, install the binary the same way, then run `backsight connect --token-file <file>` instead of `backsight setup`.

## Known limits

- Tested on Linux amd64 only.
- Open Claude Code sessions keep the server they started with after `backsight connect` until you restart them.
- The record of which memories Claude used stays on each PC: PCs sharing a server do not share it yet.
- `recall.failure_pitfalls` stays off: a replay on real failed tool calls found its matches mostly unrelated.
- A search with many results may show no kinds on its last memories: the server caps the facts it returns with them.
- The new project rule is applied to subagent reports only; on the main conversation it is measured but not applied yet.
- Project families stay off by default: a replay on real prompts showed no change yet.

Report problems at https://github.com/Barben360/backsight/issues, after reading the diagnostic `backsight report` prints, or ask Claude `/backsight:doctor`. Report vulnerabilities privately, as https://github.com/Barben360/backsight/blob/main/SECURITY.md describes.
