**Pre-release.** Linux amd64 is tested; the Linux arm64, macOS and Windows binaries are built but not tested.

Update from any earlier v0.1 with `backsight update apply`: it takes a verified backup first and rolls back if a step fails. Then restart Claude Code (or run `/reload-plugins`). New install: see below.

## What changed

**Bank names**
- New installs keep their memory in the bank `backsight` (with `backsight-docs` and `backsight-control`).
- An existing install's `claude-memory` banks move to the new names during this update, keeping every memory. backsight uses Hindsight's own rename: one transaction per bank, no LLM call. Each old name stays as an alias, so a Claude Code session started before the update keeps working.
- If the server is still busy consolidating, the update leaves the rename to tonight's `jobs maintain`, after its backup; `backsight bank rename` does it by hand. Doctor shows the old name until then.
- An archive taken before the rename restores with `server.bank = "claude-memory"`, then `backsight bank rename`.
- https://github.com/Barben360/backsight/issues/62

**Setup**
- The import of past sessions starts as setup ends, instead of at the next 15-minute tick.
- An image download that fails is tried 3 times, and the error names the cause: the network, the disk, or an image Docker could not unpack on this machine (an on-access antivirus holding containerd's mounts). troubleshooting.md has an entry for it. https://github.com/Barben360/backsight/issues/60
- `backsight secret set` run without a terminal (with `!` in Claude Code) now says so, instead of "empty value". The agent guide asks you to set keys in a terminal of your own, or piped from a password manager. https://github.com/Barben360/backsight/issues/59

**Backups**
- `backsight backup identity show` prints the key alone on stdout, so it pipes into a password manager: `backsight backup identity show | pass insert -m backsight/backup-identity`. A command with no terminal at all (an agent) is still refused. https://github.com/Barben360/backsight/issues/61

**Skills**
- New `/backsight:doctor` for backsight itself: Claude runs `doctor`, `verify --live` and the docs to find what is wrong, fixes it with your OK, and for a bug drafts a GitHub issue from `backsight report` that it files only once you confirm.
- `/backsight:memory` keeps to the memory: search, read, why. The instruction set moves to v5.

## Install

```sh
curl -fsSL https://raw.githubusercontent.com/Barben360/backsight/main/scripts/install.sh | sh
backsight setup
```

Requirements as for v0.1.3-m5: Linux amd64, Docker with Compose v2 usable without `sudo`, Claude Code 2.1.309 or newer, an LLM provider key, about 6 GB of free disk.

## Known limits

- Tested on Linux amd64 only.
- A remote server's banks are renamed on its host; its clients keep the old name and reach the bank through the alias.
- The new project rule is applied to subagent reports only; on the main conversation it is measured but not applied yet.
- Project families stay off by default: a replay on real prompts showed no change yet.
- A purge again costs a little LLM work on the server (consolidation); with the `claude-code` provider or a remote server it waits for `backsight retain purge-again --allow-subscription`.

Report problems at https://github.com/Barben360/backsight/issues, after reading the diagnostic `backsight report` prints, or ask Claude `/backsight:doctor`. Report vulnerabilities privately, as https://github.com/Barben360/backsight/blob/main/SECURITY.md describes.
