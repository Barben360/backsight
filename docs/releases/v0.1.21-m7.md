**Pre-release.** Linux amd64 is tested. Windows amd64 is new and tested in CI: GitHub's Windows runners run the unit tests and a full native install, store, backup, restore and uninstall on every change, but no standard user has run it on a real Windows 11 PC yet. The Linux arm64 and macOS binaries are built but not tested.

Update from any earlier v0.1 with `backsight update apply`: it takes a verified backup first and rolls back if a step fails. Then restart Claude Code (or run `/reload-plugins`), so the memory tools and the skills use the new binary too. New install: see below. No server change on Linux, and no change to the metrics index.

## What changed

**backsight on Windows 11 x86_64, without administrator rights**

- Install in PowerShell with `install.ps1`, which checks the release's minisign signature itself, in plain PowerShell, then the archive's SHA-256, before it runs anything. It installs under `%LOCALAPPDATA%\backsight` and adds `%LOCALAPPDATA%\Programs\backsight` to your user `PATH`, never the machine's.
- `backsight setup` runs the memory server natively by default on Windows, with no Docker. The server is Hindsight from PyPI, on PostgreSQL 18.1 with pgvector, which backsight runs from its own directory. Setup's pre-flight checks the free disk, the path length, `%` in backsight's paths, the API port, `conhost --headless` and Task Scheduler.
- A per-user scheduled task, `\backsight\server`, starts `backsight server supervise` at your logon and checks every 5 minutes that it still runs. The supervisor runs the database and the API, restarts them with backoff, and ends them with it. It answers `server status`, doctor and the other commands on a named pipe only your user can open. When a policy refuses the task, each Claude Code session starts the server instead (`server.start_on_session`).
- `backsight jobs tick` and `jobs maintain` run as two more tasks of your own. A run missed while the PC was off runs at the next chance.
- `update apply` and `uninstall` work while Claude Code sessions run the binary: the running copy is renamed aside, and uninstall's cleaner deletes what was still held once it is free.
- No step asks for elevation or writes outside your profile. The Visual C++ runtime DLLs are copied next to the programs that load them, with their SHA-256 recorded. backsight's directories and `secrets.toml` are readable by you, SYSTEM and Administrators only.
- New doctor checks on Windows: `native-task`, `supervisor`, `native-dlls`, `native-private`, `path-length` and `shim-copies`.
- `docs/windows.md` covers the install, what runs, SmartScreen and Defender, troubleshooting, and the licences of what setup downloads.

**Fixes on every platform**

- Hooks that fire at the same moment wait their turn to queue their notes, instead of one giving up on a slow disk.
- Two backsight commands opening the metrics index at once, right after an update, no longer fail on the migration the other one applied.
- A subagent's report hook stays within its kill time: when time runs short it skips naming the report's subagent, rather than being killed mid-write.

## Install

On Linux:

```sh
curl -fsSL https://raw.githubusercontent.com/Barben360/backsight/main/scripts/install.sh | sh
backsight setup
```

On Windows x86_64, in PowerShell:

```powershell
powershell -ExecutionPolicy ByPass -c "irm https://raw.githubusercontent.com/Barben360/backsight/main/scripts/install.ps1 | iex"
backsight setup
```

Requirements on Linux as for v0.1.20-m7: Linux amd64, Docker with Compose v2 usable without `sudo`, Claude Code 2.1.309 or newer, an LLM provider key, about 6 GB of free disk. For the native runtime there instead (`backsight setup --runtime native`): no Docker, a systemd user session from a login of your user, lingering on (`loginctl enable-linger`), about 3.5 GB of free disk. On Windows: Windows 11 x86_64, Claude Code 2.1.309 or newer installed natively with Git for Windows, an LLM provider key, about 3.5 GB of free disk; no Docker, no administrator rights. To join the memory of a PC already set up, install the binary the same way, then run `backsight connect --token-file <file>` instead of `backsight setup`. To put the memory server on another machine instead, run `backsight server install --ssh user@host` from a PC with OpenSSH's client; `backsight guide several-pcs` covers both.

## Known limits

- Windows is tested in CI only so far; a run on a real Windows 11 PC by a standard user comes with the next release. WSL is not tested. Windows on Arm has no binary.
- On Windows the native runtime is the only runtime: Docker there is untested, and `backsight server runtime switch` is refused. As on Linux, the native runtime serves this PC only (no `server expose --private`, no server-only host) and has no web UI.
- On Windows, the server starts with your logon, not at boot. Over SSH or with no one logged on at the screen, `backsight server start` runs it only until you log off.
- On Windows, `backsight server status` keeps showing the server's last refusal while it is stopped, until a start passes the check, even when the cause was fixed by hand.
- backsight's `.exe` files are not code-signed: SmartScreen or Smart App Control may warn about them. The install script checks the release signature before it runs anything.
- The dashboard pages are unstyled skeletons; their design comes in a later release. On a year of heavy use the Overview page can take about 0.4 s to compute (later visits within 30 seconds are instant).
- On Windows and macOS, a dashboard that crashed may leave `dashboard/dashboard.json` behind: if no dashboard runs and `backsight dashboard` says one does, delete that file (`backsight guide troubleshooting`).
- A new install reads "learning" for its first week, and some numbers read "too few" until enough prompts and turns accumulate.
- Extraction cost needs prices set under `[llm]` in the config file. The server reports token counts for all PCs together.
- On native, PostgreSQL is 18.1 with pgvector 0.8.5, where the Docker image runs 18.6 with 0.8.7; `backup verify` runs in the runtime that will restore.
- Claude cannot run `/reload-plugins`: after an update from the session, you type it.
- A LAN address carries the API key in clear; a tailnet address encrypts it.
- The shared part of a session continued on two PCs may be stored twice.
- A session part never confirmed after 24 hours is reported (doctor's `replace-unconfirmed`), not sent again automatically.

Report problems at https://github.com/Barben360/backsight/issues, after reading the diagnostic `backsight report` prints, or ask Claude `/backsight:doctor`. Report vulnerabilities privately, as https://github.com/Barben360/backsight/blob/main/SECURITY.md describes.
