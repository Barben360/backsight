**Pre-release.** Linux amd64 is tested; the Linux arm64, macOS and Windows binaries are built but not tested.

Update from any earlier v0.1 with `backsight update apply`: it takes a verified backup first and rolls back if a step fails. Then restart Claude Code (or run `/reload-plugins`), so the memory tools and the skills use the new binary too. New install: see below. No server change. The new local metrics index is created on first use (see below); `update apply` migrates it after its commit point.

## What changed

**`backsight stats <view>`: how well memory works, from the command line**

- New views, each readable as text or as JSON with `--json`:
  - `stats overview`: a verdict on four questions (does recall find something, is it right, what does it cost, does writing flow), six tiles with their change from the previous window, and what needs attention;
  - `stats quality`, `stats cost`, `stats bank`, `stats pipeline`, `stats system`: one page each;
  - `stats projects`, `stats sessions`, `stats memories`, `stats days`: lists, or one item with a name, id or date;
  - `stats releases`, and `stats defs` for what each number counts.
- Every number comes with how many events it rests on, an interval where it is a rate, and a status (`ok`, `watch`, `bad`, or why it cannot judge yet: no data, too few events).
- Common flags: `--days N`, `--since`/`--until`, `--tz`, `--project`; `--dev` adds the developer metrics. `docs/dashboard.md` explains each number and each status.
- Read-only. Server calls are GET only, 3 seconds each; a server that does not answer never fails the command, and its rows say so. Memory text appears only with `stats memories <id> --text`.
- `stats [days]`, `--since`/`--until` and `--parity` print exactly what they printed before.

**A local metrics index**

- The views read a SQLite file in the state directory (`index/metrics.db`), built from the telemetry and feedback journal files, which stay the source of truth. The first `stats <view>` or `jobs tick` builds it, printing its progress (about 10 seconds for a year of use); later runs catch up in milliseconds.
- `stats index` shows it, and `stats index rebuild` builds it again from the files. Doctor's `metrics-index` check reports a stuck or corrupt index. `uninstall --purge-local` removes it.
- The index has its own migrations. `update apply` runs them, and an older binary falls back to a side file instead of reading a newer schema.

**Telemetry**

- A recall that injects nothing records why (`prompt.empty`). Each stored note records whether it was saved, updated or refused (`store`). `feedback_error` carries a reason instead of error text.
- A subagent's report, logged as queued when it enters the notes outbox, is now also logged when it is sent. Earlier versions logged nothing after queued; the views let the outbox decide what still waits.

**Skills**

- The skills may run only the read-only `stats` commands without asking. A `stats` command that writes (`stats index rebuild --yes`) always asks.
- The instruction set is now v11.

## Install

```sh
curl -fsSL https://raw.githubusercontent.com/Barben360/backsight/main/scripts/install.sh | sh
backsight setup
```

Requirements as for v0.1.18-m7: Linux amd64, Docker with Compose v2 usable without `sudo`, Claude Code 2.1.309 or newer, an LLM provider key, about 6 GB of free disk. For the native runtime instead (`backsight setup --runtime native`): no Docker, a systemd user session from a login of your user, lingering on (`loginctl enable-linger`), about 3.5 GB of free disk. To join the memory of a PC already set up, install the binary the same way, then run `backsight connect --token-file <file>` instead of `backsight setup`. To put the memory server on another machine instead, run `backsight server install --ssh user@host` from a PC with OpenSSH's client; `backsight guide several-pcs` covers both.

## Known limits

- Tested on Linux amd64 only. The native runtime runs on Linux x86_64 only, is not tested on WSL, serves this PC only (no `server expose --private`, no server-only host) and has no web UI.
- The views are command-line only. The `backsight dashboard` web page comes in a later release.
- A new install reads "learning" for its first week, and some numbers read "too few" until enough prompts and turns accumulate.
- Extraction cost needs prices set under `[llm]` in the config file. The server reports token counts for all PCs together.
- On native, PostgreSQL is 18.1 with pgvector 0.8.5, where the Docker image runs 18.6 with 0.8.7; `backup verify` runs in the runtime that will restore.
- Claude cannot run `/reload-plugins`: after an update from the session, you type it.
- A LAN address carries the API key in clear; a tailnet address encrypts it.
- The shared part of a session continued on two PCs may be stored twice.
- A session part never confirmed after 24 hours is reported (doctor's `replace-unconfirmed`), not sent again automatically.

Report problems at https://github.com/Barben360/backsight/issues, after reading the diagnostic `backsight report` prints, or ask Claude `/backsight:doctor`. Report vulnerabilities privately, as https://github.com/Barben360/backsight/blob/main/SECURITY.md describes.
