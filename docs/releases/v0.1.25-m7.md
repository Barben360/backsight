**Pre-release.** Linux amd64 is tested; Windows amd64 is tested in CI, with no new run on a Windows PC for this release. The Linux arm64 and macOS binaries are built but not tested.

Update from any earlier v0.1 with `backsight update apply`: it takes a verified backup first and rolls back if a step fails. Then restart Claude Code and a running dashboard (Ctrl+C, then `backsight dashboard`). New install: see below. The server image is unchanged. The memory bank gains a rule for imported files, written at the first import; on a PC joined to another PC's server, update the server's computer first, or `backsight import` stops and says so. No change to the metrics index's tables.

## What changed

- **Import a folder of notes** (https://github.com/Barben360/backsight/issues/150): `backsight import <folder>` sends Markdown and text files into the memory. That can be another tool's memory files (LifeOS, a notes vault) or your own notes. Each file becomes one document. `--plan` shows the files, the facts to expect and the cost per folder, changing nothing. The import then runs in the background through `jobs tick` (10 files per run, after any past sessions) within a spending cap: 1.5 times the estimate by default, or `--max-cost` / `--max-tokens`. Secrets are hidden before sending, and a file's `date:` header becomes the memory's date. `--exclude` skips paths, `--ext jsonl` adds an extension, and `--project` picks the project (default: the transverse one). A rerun sends only new and changed files. `backsight import list` shows each folder's progress and spend, and `backsight import purge <id>` deletes everything a folder put in the memory. Setup asks about it too (default no), and the new `docs/import.md` has a LifeOS recipe.
- `backsight stats bank` and the dashboard's Bank page count the files imported over the window, with the imports started, finished, paused at the cap and removed.
- **Sends wait while the server's model fails to extract** (https://github.com/Barben360/backsight/pull/151): when the provider rejects the key or has no credit, `jobs tick` holds every send (sessions, notes, backfill, imports) instead of losing them. It tries the provider again on each tick and resumes once it answers. The session banner, `store` and doctor's `bank` check say so, with the fix.
- **A prompt that only points at an issue, a PR or a link is read before memory is searched** (https://github.com/Barben360/backsight/pull/156): searching such a prompt mostly found loose matches on the project name. Now that prompt is not searched, and Claude is told to read what it points at, then search by its content. The next prompt still recalls as if it were the first. Instruction set v12.
- **`backsight retain resend-failed`** (https://github.com/Barben360/backsight/pull/152): sends again the sessions whose parts failed on the server while extraction was failing. It lists them with the cost, asks before deleting their documents, and takes a verified backup first. doctor's `replace-unconfirmed` and `bank` checks now point to it.

## Install

On Linux:

```sh
curl -fsSL https://raw.githubusercontent.com/Barben360/backsight/main/scripts/install.sh | sh
backsight setup
```

On Windows x86_64, in PowerShell:

```powershell
powershell -ExecutionPolicy ByPass -c "irm https://raw.githubusercontent.com/Barben360/backsight/main/scripts/install.ps1 | iex"
backsight setup
```

Requirements as for v0.1.22-m7. On Windows, Claude Code must find Git Bash: if Git for Windows is portable or installed in a place of your own, set `CLAUDE_CODE_GIT_BASH_PATH` to its `bin\bash.exe` (doctor's `git-bash` check gives the command).

## Known limits

- Import: a file the server keeps rejecting holds that folder's next files until it passes. The last tick before a cap can overshoot it by what was already in flight. A file deleted from the folder stays in the memory until `import purge`. Not yet tried on a real server: the tests run against a fake one.
- `retain resend-failed` does not cover notes and sub-agent reports sent while extraction failed: the queue drops them once sent.
- Windows: WSL is not tested, and Windows on Arm has no binary. The native runtime is the only runtime there (`server runtime switch` is refused), it serves this PC only and has no web UI. The server starts with your logon, not at boot.
- On Windows, `backsight server status` keeps showing the server's last refusal while it is stopped, until a start passes the check.
- backsight's `.exe` files are not code-signed: SmartScreen or Smart App Control may warn about them. The install script checks the release signature before it runs anything.
- Dashboard: the project filter takes a typed name, not a pick from a list (the Projects page lists the names); the Projects list cannot be sorted; the context card names the session budget rather than showing its value.
- A new install reads "learning" for its first week, and some numbers read "too few" until enough prompts and turns accumulate.
- Extraction cost needs prices set under `[llm]` in the config file. The server reports token counts for all PCs together.
- On native, PostgreSQL is 18.1 with pgvector 0.8.5, where the Docker image runs 18.6 with 0.8.7; `backup verify` runs in the runtime that will restore.
- Claude cannot run `/reload-plugins`: after an update from the session, you type it.
- A LAN address carries the API key in clear; a tailnet address encrypts it.
- The shared part of a session continued on two PCs may be stored twice.
