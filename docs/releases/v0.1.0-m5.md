**Pre-release.** This is backsight's first public release. It works and is used every day, but expect rough edges. It is tested on Linux amd64 only.

## What it is

backsight gives Claude Code a long-term memory, kept on a [Hindsight](https://github.com/vectorize-io/hindsight) server that you run on your own machine. When a session ends, its text is redacted and sent to your server, which extracts durable facts: decisions, fixes, conventions, pitfalls. Later sessions start with a briefing on the current project, and each prompt brings in the few memories that matter.

backsight is one Go binary. It installs the server in Docker, wires it into Claude Code, and keeps it running: signed updates, encrypted daily backups, `backsight doctor` checks.

## Who it is for

Claude Code users on Linux who are comfortable with a terminal and Docker, and who accept a pre-release.

## Requirements

- Linux amd64. The Linux arm64, macOS and Windows binaries are built but not tested.
- Docker with Compose v2 (the `docker compose` plugin), usable by your user without `sudo`. Joining the `docker` group gives your user root-level access to the machine.
- Claude Code 2.1.309 or newer.
- An LLM provider for the server to extract memories with. A DeepSeek, Anthropic or OpenAI API key, or a compatible endpoint, is the tested path. DeepSeek costs about $0.14 per million input tokens. You pay the provider per use, separately from any Claude plan, and `backsight stats` shows the tokens used.
- About 6 GB of free disk. The first setup downloads about 2.3 GB: the server image, and its embedding models from Hugging Face.

## Install

```sh
curl -fsSL https://raw.githubusercontent.com/Barben360/backsight/main/scripts/install.sh | sh
backsight setup
```

The script checks the release's minisign signature and checksum before it installs anything. `backsight setup` asks a few questions, shows its plan and asks for your consent before it changes anything. When it is done, restart Claude Code and run `backsight doctor`.

To check a download by hand, with [`minisign.pub`](https://github.com/Barben360/backsight/blob/main/minisign.pub): `minisign -Vm checksums.txt -p minisign.pub`, then `sha256sum -c checksums.txt --ignore-missing`.

## Known limits

- **Docker 26 (for example Debian 13's `docker.io`)**: when your user cannot reach Docker (not in the `docker` group, or the daemon stopped), setup's pre-flight and `doctor` still report Docker as ok. Setup then fails at the server step with a raw `docker.sock` permission error. Fix: `sudo usermod -aG docker $USER`, log out and back in, then run `backsight setup` again.
- **A wrong or rejected LLM key**: the server step fails with the provider's raw error. After `backsight secret set llm_api_key`, `backsight setup --resume` then says that ports 8888 and 9999 are taken: backsight's own server holds them. Run `backsight server stop`, then `backsight setup --resume`.
- **First download**: setup prints nothing while it downloads the image and the models, which can take more than ten minutes on a slow link.
- **Ollama on Linux**: the server container cannot reach an Ollama on the host at the default address. Use an API provider for now.
- **Redaction**: some secret shapes pass the redaction before storage, among them backsight's own backup key (`AGE-SECRET-KEY-…`), netrc passwords, Docker auth, webhook URLs, PGP private key blocks and Azure keys. See https://github.com/Barben360/backsight/issues/9.
- **After `forget --purge`**: an older backsight binary still running elsewhere can bring back turns of a purged session. See https://github.com/Barben360/backsight/issues/5.
- **Uninstall** leaves the server's Docker images (about 3 GB, shown as `<none>` by `docker images`) and an empty anonymous volume.
- **`doctor` after a reinstall** can count a backup from the previous install as healthy, even when this install cannot read it.
- Some setup questions, help texts and doctor checks cite internal design references: numbered decisions and experiment codes. They mean nothing to you, and the next release removes them.

Report problems at https://github.com/Barben360/backsight/issues, after reading the diagnostic `backsight report` prints. Report vulnerabilities privately, as https://github.com/Barben360/backsight/blob/main/SECURITY.md describes.
