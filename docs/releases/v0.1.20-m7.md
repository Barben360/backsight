**Pre-release.** Linux amd64 is tested; the Linux arm64, macOS and Windows binaries are built but not tested.

Update from any earlier v0.1 with `backsight update apply`: it takes a verified backup first and rolls back if a step fails. Then restart Claude Code (or run `/reload-plugins`), so the memory tools and the skills use the new binary too. New install: see below. No server change, and no change to the metrics index.

## What changed

**`backsight dashboard`: the stats views in a browser**

- `backsight dashboard` serves the `stats` views as web pages, on this machine only (`127.0.0.1`), and prints a one-time link. Open it within 2 minutes, from a terminal or the address bar. `backsight dashboard link` prints a new one for the running dashboard.
- Pages: Overview, Quality, Cost, Bank, Pipeline and System, and under Browse the projects, sessions and memories, each with a page per item. Every number on a page is what `backsight stats <view> --json` prints. A memory's text shows only on its own page, after a click on "Show text", read live from the server and never stored.
- Flags: `--port <n>` for a fixed port, `--open` to start your browser with the link, `--json` for `{url, port, expires_at}`. It runs in the foreground: Ctrl+C stops it, and it stops on its own after 2 hours without a signed-in request. One dashboard runs at a time.
- From another PC: forward the same port on both ends with `ssh -L 8765:127.0.0.1:8765 <user>@<host>`, as `docs/dashboard.md` explains.
- Hardened for a local web page:
  - the browser signs in with a one-time code, then holds a cookie that expires after 2 hours without use;
  - requests for another host name, from another site, or with another method than GET are refused;
  - pages forbid framing, scripts from elsewhere and referrers;
  - the server is read with GET only.
- `docs/privacy.md` says what the pages show and what stays on the PC. It also says what a browser's sign-in cookie can reach: browsers send it to every service on `127.0.0.1`, whatever the port.
- The pages are plain for now: a later release brings their design.

**Agents**

- The agent guide says agents never start the dashboard on their own. When you ask, they run `backsight dashboard --open` in the background or give you a link with `backsight dashboard link`. For numbers they keep using `backsight stats <view> --json`. The instruction set is unchanged (v11).

## Install

```sh
curl -fsSL https://raw.githubusercontent.com/Barben360/backsight/main/scripts/install.sh | sh
backsight setup
```

Requirements as for v0.1.19-m7: Linux amd64, Docker with Compose v2 usable without `sudo`, Claude Code 2.1.309 or newer, an LLM provider key, about 6 GB of free disk. For the native runtime instead (`backsight setup --runtime native`): no Docker, a systemd user session from a login of your user, lingering on (`loginctl enable-linger`), about 3.5 GB of free disk. To join the memory of a PC already set up, install the binary the same way, then run `backsight connect --token-file <file>` instead of `backsight setup`. To put the memory server on another machine instead, run `backsight server install --ssh user@host` from a PC with OpenSSH's client; `backsight guide several-pcs` covers both.

## Known limits

- Tested on Linux amd64 only. The native runtime runs on Linux x86_64 only, is not tested on WSL, serves this PC only (no `server expose --private`, no server-only host) and has no web UI.
- The dashboard pages are unstyled skeletons; their design comes in a later release. On a year of heavy use the Overview page can take about 0.4 s to compute (later visits within 30 seconds are instant).
- On Windows and macOS, a dashboard that crashed may leave `dashboard/dashboard.json` behind: if no dashboard runs and `backsight dashboard` says one does, delete that file (`backsight guide troubleshooting`).
- A new install reads "learning" for its first week, and some numbers read "too few" until enough prompts and turns accumulate.
- Extraction cost needs prices set under `[llm]` in the config file. The server reports token counts for all PCs together.
- On native, PostgreSQL is 18.1 with pgvector 0.8.5, where the Docker image runs 18.6 with 0.8.7; `backup verify` runs in the runtime that will restore.
- Claude cannot run `/reload-plugins`: after an update from the session, you type it.
- A LAN address carries the API key in clear; a tailnet address encrypts it.
- The shared part of a session continued on two PCs may be stored twice.
- A session part never confirmed after 24 hours is reported (doctor's `replace-unconfirmed`), not sent again automatically.
