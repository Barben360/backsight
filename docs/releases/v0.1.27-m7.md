**Pre-release.** Linux amd64 is tested; Windows amd64 is tested in CI, with no new run on a Windows PC for this release. The Linux arm64 and macOS binaries are built but not tested.

Update from any earlier v0.1 with `backsight update apply`: it takes a verified backup first and rolls back if a step fails. Then restart Claude Code and a running dashboard (Ctrl+C, then `backsight dashboard`). New install: see below.
- The server moves to Hindsight 1.2.0: the update runs a server upgrade, on the PC that runs the server. With the Docker runtime it pulls the new image; with the native runtime it builds the new Python environment beside the running one. The memory is unavailable while the new version starts. Hindsight 1.2.0 changes nothing in the database, and an older backup restores as is.
- The instruction set is unchanged (v12), and so is the metrics index.

## What changed

- **Hindsight 1.2.0, with its security fixes on Docker too** (https://github.com/Barben360/backsight/pull/175): the new image ships authlib 1.9.1, dnspython 2.9.0, fastmcp 3.4.11 and OpenTelemetry 1.45.1, which only the native runtime had until now. The native runtime keeps one package newer than the image (pyasn1 0.6.5), and now runs Python 3.11.18, as the image does.
- **Claude can retire a wrong memory of another project** (https://github.com/Barben360/backsight/issues/170): search shows memories from every project, but `memory_credit` could only retire those of the session's project, the projects it links and the transverse pool. A wrong fact of another project kept coming back until you ran `backsight forget <id>`. Now Claude retires it, and the correction is stored in that memory's project. The other limits hold: shown in this session, a correction with its evidence, `max_retirements` per session (counting every project), never a project kept out of memory, and reversible with `backsight forget --restore <id>`. `backsight memory stale` and `backsight stats` list these retirements with both projects. To keep the old rule, set `feedback.cross_project_retire = false` in `config.toml`; a repository's `.backsight.toml` cannot change it.
- **`retain resend-failed` sends sessions back that ran in a deleted worktree** (https://github.com/Barben360/backsight/issues/168): a session was held as `directory gone` as soon as one of its directories no longer existed, which held back most sessions to recover. Those turns now go under the project this PC recorded for them when they ran. A session is still held when that project was not recorded, or when today's rules would file the turns under another; its reason then names each such directory. `--plan` now lists the sessions while retains are still queued on the server (it exits 20, as nothing can be sent yet).
- **Doctor's `transcripts` warning no longer counts record types backsight knows** (https://github.com/Barben360/backsight/issues/167): Claude Code's new `session-owner`, `history-suppression` and `fork-context-ref` records are known, and records that an older backsight counted as unknown stop counting at once instead of after 7 days.
- **The GPU reranker page says an integrated GPU counts** (https://github.com/Barben360/backsight/pull/172): the GPU built into most laptops' processors (recent AMD Ryzen, Intel Iris Xe or Arc) takes the AMD or Intel recipe and uses the system's RAM. A laptop that also has an NVIDIA GPU should use that one. `backsight guide gpu-reranker`.

## Install

On Linux:

```sh
curl -fsSL https://raw.githubusercontent.com/Barben360/backsight/main/scripts/install.sh | sh
backsight setup
```

On Windows x86_64, in PowerShell:

```powershell
powershell -ExecutionPolicy ByPass -c "irm https://raw.githubusercontent.com/Barben360/backsight/main/scripts/install.ps1 | iex"
backsight setup
```

Requirements as for v0.1.22-m7. On Windows, Claude Code must find Git Bash: if Git for Windows is portable or installed in a place of your own, set `CLAUDE_CODE_GIT_BASH_PATH` to its `bin\bash.exe` (doctor's `git-bash` check gives the command).

## Known limits

- GPU reranker:
  - It needs the Docker runtime, on the server's PC.
  - Tested on one NVIDIA RTX A2000 (Linux) and one AMD Radeon 890M (Linux). Intel GPUs, macOS and Windows are not tested.
- Owner checks:
  - The short-lived native units created during install, start and restore are not checked.
  - On Windows, when neither `schtasks` nor the task's file can be read, the task is driven as before.
- Python packages with a published advisory: filelock 3.20.3, on both runtimes, because litellm requires a version below 4.0 and no fixed version exists below 4.0; pyasn1 0.6.4 in the Docker image (native runs 0.6.5) (https://github.com/Barben360/backsight/issues/130).
- `retain resend-failed`: it does not cover notes and sub-agent reports sent while extraction failed (the queue drops them once sent). A transcript rewritten or moved after its worktree was deleted loses the project recorded for those turns, so the session is then filed by today's rules.
- Import: a file the server keeps rejecting holds that folder's next files until it passes. The last tick before a cap can overshoot it by what was already in flight. A file deleted from the folder stays in the memory until `import purge`.
- Windows:
  - WSL is not tested, and Windows on Arm has no binary.
  - The native runtime is the only runtime there (`server runtime switch` is refused). It serves this PC only, has no web UI, and starts with your logon, not at boot.
  - `backsight server status` keeps showing the server's last refusal while it is stopped, until a start passes the check.
  - backsight's `.exe` files are not code-signed: SmartScreen or Smart App Control may warn about them. The install script checks the release signature before it runs anything.
- Dashboard: the project filter takes a typed name, not a pick from a list (the Projects page lists the names). The Projects list cannot be sorted. The context card names the session budget rather than showing its value.
- A new install reads "learning" for its first week, and some numbers read "too few" until enough prompts and turns accumulate.
- Extraction cost needs prices set under `[llm]` in the config file. The server reports token counts for all PCs together.
- On native, PostgreSQL is 18.1 with pgvector 0.8.5, where the Docker image runs 18.6 with 0.8.7; `backup verify` runs in the runtime that will restore.
- Claude cannot run `/reload-plugins`: after an update from the session, you type it.
- A LAN address carries the API key in clear; a tailnet address encrypts it.
- The shared part of a session continued on two PCs may be stored twice.
