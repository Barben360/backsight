**Pre-release.** Linux amd64 is tested; Windows amd64 is tested in CI, with no new run on a Windows PC for this release. The Linux arm64 and macOS binaries are built but not tested.

Update from any earlier v0.1 with `backsight update apply`: it takes a verified backup first and rolls back if a step fails. Then restart Claude Code and a running dashboard (Ctrl+C, then `backsight dashboard`). New install: see below.
- The server is unchanged (Hindsight 1.2.0): no server upgrade.
- The instruction set is unchanged (v12), and so is the metrics index's schema.

## What changed

- **New numbers in `backsight stats`** (https://github.com/Barben360/backsight/pull/190): every one is in `backsight stats <view> --json`; the dashboard pages draw them in a later release.
  - `pipeline.time_to_recall` (pipeline): from a session's last turn to sent, extracted and first shown, with middle and slow times per step.
  - `memory.yield` (cost): per week, the share of new memories used within 28 days, and the extraction tokens per useful memory.
  - `bank.growth` and `extraction.tokens` reach past the days the server keeps, from this PC's daily record.
  - `secrets.suspects` (system): the last `backsight memory scan`'s count. Above 0, the Overview's Flowing axis is on watch and says "Possible secrets in memory: run backsight memory scan."
  - `doctor.history` (system): each check's status per day.
  - The 3 memories that helped most in the window, a 13-month calendar in `stats days`, and a marker at each version switch and settings change on this PC.
  - `stats releases --compare A,B [--measure used.turn_rate|recall.hit_rate|verdict.wrong_rate]` compares two versions over the same projects and paths, with a 95 % interval. It says "differs" or "no clear difference", or "too few" with what is missing and when to retry.
  - `stats sessions --has never_extracted|contradicted`.
- **`backsight retain waiting`** (https://github.com/Barben360/backsight/issues/181): lists each session this PC has not sent yet and why: still being written (it settles 30 min after its last turn), due at the next tick, or quarantined. Notes queued or set aside are counted too. The local backlog's hint said "run backsight jobs tick", which moves none of the first and last kinds; it now points at this command.
- **A fixed slowness stops warning before the week is over** (https://github.com/Barben360/backsight/issues/184): when the last 24 h have at least 20 recalls and their p95 is back under the watch line, doctor's `latency` check drops from warning to info ("improving") and `recall.latency` from bad to watch. The 7-day figure is still shown, and a still-slow day changes nothing.
- **Doctor's bank check after an extraction outage** (https://github.com/Barben360/backsight/issues/182): "they succeed again since" names the first success after the last failure (it moved at every run). A last failure older than 7 days is info, no longer a warning; within the week, the warning says when it ends.
- **The metrics index** (https://github.com/Barben360/backsight/issues/128):
  - A folder that looks local but cannot give the write-ahead log (some FUSE mounts) is now found: backsight tests it once on a scratch file when it creates the index, and otherwise runs the index without it, syncing every commit. On Windows, a mapped network drive (`Z:\`) counts as a network folder. An index already in write-ahead mode is unchanged.
  - An older backsight that opens the index while a newer one migrates it now uses its own side file, instead of writing into the newer schema.
  - The daily integrity check, when it runs out of its 10 s, waits a day before it tries again instead of running at every open.
  - `backsight stats index rebuild` drops what is older than 25 months, as the daily maintenance does. Its "in use" message names any backsight process (the dashboard, a jobs tick or a command), not only the dashboard.
  - A jobs tick that gives way to another backsight process holding the index says so ("yielded"). Doctor's index check reads `timeout` only when its time bound really cut the check short.
  - Session and memory ids that contain whitespace are refused when lines are read into the index.
- **The Overview loads faster**: its quality numbers take about 40 % less time (one read per turn's final stop, prompts read once for all windows).
- **Smaller fixes**: `stats`' local backlog counts quarantined sessions, as doctor and `backsight report` do (https://github.com/Barben360/backsight/issues/180). `stats defs` says that the `unknown` reason of `recall.empty_reasons` only covers recalls logged before v0.1.19 (https://github.com/Barben360/backsight/issues/183).

## Install

On Linux:

```sh
curl -fsSL https://raw.githubusercontent.com/Barben360/backsight/main/scripts/install.sh | sh
backsight setup
```

On Windows x86_64, in PowerShell:

```powershell
powershell -ExecutionPolicy ByPass -c "irm https://raw.githubusercontent.com/Barben360/backsight/main/scripts/install.ps1 | iex"
backsight setup
```

Requirements as for v0.1.22-m7. On Windows, Claude Code must find Git Bash: if Git for Windows is portable or installed in a place of your own, set `CLAUDE_CODE_GIT_BASH_PATH` to its `bin\bash.exe` (doctor's `git-bash` check gives the command).

## Known limits

- GPU reranker:
  - It needs the Docker runtime, on the server's PC.
  - Tested on one NVIDIA RTX A2000 (Linux) and one AMD Radeon 890M (Linux). Intel GPUs, macOS and Windows are not tested.
- Owner checks:
  - The short-lived native units created during install, start and restore are not checked.
  - On Windows, when neither `schtasks` nor the task's file can be read, the task is driven as before.
- Python packages with a published advisory: filelock 3.20.3, on both runtimes, because litellm requires a version below 4.0 and no fixed version exists below 4.0; pyasn1 0.6.4 in the Docker image (native runs 0.6.5) (https://github.com/Barben360/backsight/issues/130).
- `retain resend-failed`: it does not cover notes and sub-agent reports sent while extraction failed (the queue drops them once sent). A transcript rewritten or moved after its worktree was deleted loses the project recorded for those turns, so the session is then filed by today's rules.
- The local backlog's age can stay high with nothing left to send, when a document's last recorded send stayed queued or retrying; `backsight retain waiting` then lists nothing.
- The metrics index: an index already in write-ahead mode whose folder no longer allows it fails its writes until the state directory is back on a local disk. `stats days` reads a year of prompts with no index for it (about 0.1 s locally).
- Import: a file the server keeps rejecting holds that folder's next files until it passes. The last tick before a cap can overshoot it by what was already in flight. A file deleted from the folder stays in the memory until `import purge`.
- Windows:
  - WSL is not tested, and Windows on Arm has no binary.
  - The native runtime is the only runtime there (`server runtime switch` is refused). It serves this PC only, has no web UI, and starts with your logon, not at boot.
  - `backsight server status` keeps showing the server's last refusal while it is stopped, until a start passes the check.
  - backsight's `.exe` files are not code-signed: SmartScreen or Smart App Control may warn about them. The install script checks the release signature before it runs anything.
- Dashboard: the project filter takes a typed name, not a pick from a list (the Projects page lists the names). The Projects list cannot be sorted. The context card names the session budget rather than showing its value. The new numbers of this release are not drawn yet.
- A new install reads "learning" for its first week, and some numbers read "too few" until enough prompts and turns accumulate.
- Extraction cost needs prices set under `[llm]` in the config file. The server reports token counts for all PCs together.
- On native, PostgreSQL is 18.1 with pgvector 0.8.5, where the Docker image runs 18.6 with 0.8.7; `backup verify` runs in the runtime that will restore.
- Claude cannot run `/reload-plugins`: after an update from the session, you type it.
- A LAN address carries the API key in clear; a tailnet address encrypts it.
- The shared part of a session continued on two PCs may be stored twice.

Report problems at https://github.com/Barben360/backsight/issues, after reading the diagnostic `backsight report` prints, or ask Claude `/backsight:doctor`. Report vulnerabilities privately, as https://github.com/Barben360/backsight/blob/main/SECURITY.md describes.
