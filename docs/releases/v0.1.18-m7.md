**Pre-release.** Linux amd64 is tested; the Linux arm64, macOS and Windows binaries are built but not tested.

Update from any earlier v0.1 with `backsight update apply`: it takes a verified backup first and rolls back if a step fails. Then restart Claude Code (or run `/reload-plugins`), so the memory tools and the skills use the new binary too. New install: see below. No migration and no server change.

## What changed

**The switch to native works on an install with backsight's default directories**

- `backsight server runtime switch native` stopped at its `target` step: the database unit's check before each start (`server native-check`) looked for backsight's config under the unit's own `HOME`, pg0's directory, and found none ("no config at …/server/native/home/.config/backsight/config.toml"). It now runs with your `HOME`. Only installs that set `BACKSIGHT_HOME` or `XDG_CONFIG_HOME` worked before, so `setup --runtime native` on a default install failed the same way. In v0.1.17-m7 the switch rolled back and Docker kept running, with nothing lost; run the switch again after this update.
- The instruction set stays v10; JSON outputs are unchanged.

## Install

```sh
curl -fsSL https://raw.githubusercontent.com/Barben360/backsight/main/scripts/install.sh | sh
backsight setup
```

Requirements as for v0.1.17-m7: Linux amd64, Docker with Compose v2 usable without `sudo`, Claude Code 2.1.309 or newer, an LLM provider key, about 6 GB of free disk. For the native runtime instead (`backsight setup --runtime native`): no Docker, a systemd user session from a login of your user, lingering on (`loginctl enable-linger`), about 3.5 GB of free disk. To join the memory of a PC already set up, install the binary the same way, then run `backsight connect --token-file <file>` instead of `backsight setup`. To put the memory server on another machine instead, run `backsight server install --ssh user@host` from a PC with OpenSSH's client; `backsight guide several-pcs` covers both.

## Known limits

- Tested on Linux amd64 only. The native runtime runs on Linux x86_64 only, is not tested on WSL, serves this PC only (no `server expose --private`, no server-only host) and has no web UI.
- On native, PostgreSQL is 18.1 with pgvector 0.8.5, where the Docker image runs 18.6 with 0.8.7; `backup verify` runs in the runtime that will restore.
- The switch's comparison covers row counts, keys, banks and backsight's documents, not every column's content.
- A plain `doctor` shows the size of what a switch kept for a day after the switch; `doctor --json` measures it again.
- Claude cannot run `/reload-plugins`: after an update from the session, you type it.
- A LAN address carries the API key in clear; a tailnet address encrypts it.
- The shared part of a session continued on two PCs may be stored twice.
- A session part never confirmed after 24 hours is reported (doctor's `replace-unconfirmed`), not sent again automatically.

Report problems at https://github.com/Barben360/backsight/issues, after reading the diagnostic `backsight report` prints, or ask Claude `/backsight:doctor`. Report vulnerabilities privately, as https://github.com/Barben360/backsight/blob/main/SECURITY.md describes.
