**Pre-release.** Linux amd64 is tested; the Linux arm64, macOS and Windows binaries are built but not tested.

Update from any earlier v0.1 with `backsight update apply`: it takes a verified backup first and rolls back if a step fails. Then restart Claude Code (or run `/reload-plugins`), so `memory_search` uses the new binary too. New install: see below. No migration and no server change.

## What changed

**Your PCs learn from each other's counts**
- PCs that use one memory server now share the record of which memories Claude used. Recall on each PC ranks with the uses and misses counted on all of them, so a memory Claude often uses on your laptop also rises on your desktop.
- What is shared: for each memory counted, its id, its uses and misses (numbers), when they were counted and when it was hidden, plus a random id of the machine that sent them. Never memory or conversation text, a session or a project. It goes to one document per machine in your own server's control bank (`<bank>-control`), and nowhere else.
- When: the 15-minute maintenance job (`jobs tick`) sends this machine's counts when they changed (at most once an hour), at once when a memory was hidden or restored, and once a week even when nothing changed. It fetches the other machines' counts every 6 hours. What one machine counted therefore reaches the others within about 6 hours.
- An observation hidden on one machine, after Claude reported it wrong or outdated, is hidden on the others too, from their next fetch.
- `backsight forget --restore <id>` applies on the machine where you run it. It shows the memory again there, even when another machine hid it, and the other machines keep hiding it. Run it on each machine where you want the memory back.
- A machine silent for 30 days no longer counts.
- Recall never waits on the server for this: it reads the copy the job fetched last. When that copy is missing or cannot be read, recall ranks with this machine's counts alone, as before.
- `backsight stats` adds to its `Ledger` line how many other machines recall weighs ("shared with 2 other machines"; `shared_machines` in `--json`). `backsight memory stale`, `backsight feedback replay` and the counts of `stats` stay this machine's own.
- The tick's line says when it sent this machine's counts, how many other machines' counts it holds, and why it could not share them.
- doctor's new `feedback-shared` check warns when the other machines' counts were not fetched for more than a day while the server answers.
- New setting `share_ledger` under `[feedback]` in `config.toml`, on by default. `share_ledger = false` stops this machine from both sending and reading the counts. What it sent last stays on the server, and the other machines ignore it after 30 days. backsight never writes this setting; v0.1.10-m6 refuses a `config.toml` that has it, so remove it before going back.
- A PC still on an older version ignores these documents: it keeps ranking with its own counts, and sends none until it is updated.

## Install

```sh
curl -fsSL https://raw.githubusercontent.com/Barben360/backsight/main/scripts/install.sh | sh
backsight setup
```

Requirements as for v0.1.10-m6: Linux amd64, Docker with Compose v2 usable without `sudo`, Claude Code 2.1.309 or newer, an LLM provider key, about 6 GB of free disk. To join the memory of a PC already set up, install the binary the same way, then run `backsight connect --token-file <file>` instead of `backsight setup`. To put the memory server on another machine instead, run `backsight server install --ssh user@host` from a PC with OpenSSH's client; the host needs Linux on x86_64 or aarch64, Docker with Compose v2, `tar`, and `minisign` or OpenSSL 3.

## Known limits

- Tested on Linux amd64 only. `backsight server install --ssh` is tested against simulated hosts, not yet over a real ssh connection.
- A memory hidden on one PC still shows on your other PCs until their next fetch, up to about 6 hours later.
- `backsight feedback replay` compares only the recalls recorded from v0.1.10-m6 on: older ones lack the score it needs and are counted apart as not comparable. It can only reorder the memories a recall kept, so a change of hits shows only for a recall that kept more memories than `recall.prompt_hits`.
- The list of similar memories Claude sees when it stores one can still hold a hidden observation.
- Open Claude Code sessions keep the server they started with after `backsight connect` until you restart them.
- `recall.failure_pitfalls` stays off: a replay on real failed tool calls found its matches mostly unrelated.
- A search with many results may show no kinds on its last memories: the server caps the facts it returns with them.
- The new project rule is applied to subagent reports only; on the main conversation it is measured but not applied yet.
- Project families stay off by default: a replay on real prompts showed no change yet.
