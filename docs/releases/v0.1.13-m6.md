**Pre-release.** Linux amd64 is tested; the Linux arm64, macOS and Windows binaries are built but not tested.

Update from any earlier v0.1 with `backsight update apply`: it takes a verified backup first and rolls back if a step fails. Then restart Claude Code (or run `/reload-plugins`), so `memory_search` uses the new binary too. New install: see below. No migration and no server change.

## What changed

**One memory for all your PCs, complete**

One PC holds the memory server (the host), and your other PCs use it. On the host, `backsight server expose --private <address> --out <file>` opens the server on a private address and writes the connection token; `backsight server token --out <file>` writes it again, `--rotate` gives the server a new key. On each other PC, `backsight connect --token-file <file>` joins. `backsight server install --ssh user@host` installs the server on another machine and joins it in one command. The new page `backsight guide several-pcs` walks through all of it: choosing the host, the token, away from home, a lost laptop, restore and purge, a session continued on two PCs.

New in this release:
- `backsight stats` has a `Server` line, from what this PC last recorded at each recall and `jobs tick` (no call to the server): `answering (last answer 5m ago)`, `silent since <time> (<age>)` with whether recall is paused and how many notes and sessions wait, or, on a PC that joined another's server, `a different server answers at <host> … writes held` while another server answers at its address. A client names the server's host, never its port or key.
- `backsight doctor` has a `replace-unconfirmed` check: it warns when, in the last 30 days, this PC gave up checking a part of a session it sent (below), and names up to 5 of them. `backsight guide troubleshooting#doctor-a-session-part-was-never-confirmed` says what to do.
- `backsight verify --live` passes a session continued on another PC, and names it ("continued on another PC: …", `continued_elsewhere` in `--json`).
- A server on an address that appears late (Tailscale, DHCP) is still started again by the 15-minute job and at session start, but a start that fails is no longer repeated at every look: the next waits 15 minutes, then twice as long each time up to 6 hours. The count starts over once a `backsight server start` brings the server up (the background one or yours), once backsight sees the server stopped by you or no longer on a private address, or, on Linux, after a reboot. `server-start.log` over 1 MiB moves to `server-start.log.1`.
- A memory server that drops packets without answering costs a prompt about 3 seconds, not the whole 17-second recall budget: the connection itself is now bounded.
- `backsight server install --ssh` is now tested over a real OpenSSH connection between two machines.
- The troubleshooting page has an entry for every doctor and setup check.
- Asked to put the memory server on another machine, Claude no longer runs `backsight server install --ssh` itself: it shows the plan (`--plan`, which reads no key and changes nothing), and you run the install in a terminal of your own, so the LLM key never passes through Claude.

**Fixed**
- A send that read this PC's settings just before `backsight connect` switched servers (a session's end, `retain flush`, `jobs tick`, `retain backfill`) no longer reaches the old server after it. A session start during a connect no longer creates the project's briefing page on the old server; the next session creates it on the new one.
- A session continued on two PCs is numbered after the other PC's part: each PC reads the session's document before appending to it. Before, both PCs could send a part under the same number, and `verify --live` reported a loss that was not one.
- That read also checks the part number the server's document holds: when it is not a valid one, the session is quarantined instead of sent, since sending could replace the document. Before, this was checked only when backsight rebuilt its position from the server. Fix the cause, then `backsight retain retry-quarantine`.
- When two PCs send the first part of the same session before the server stores either, the server keeps only the later one. The PC whose part was replaced now sends its missing turns again, as the next part, at a `jobs tick` at least 5 minutes after its send. A part it cannot confirm within 24 hours is given up and reported by doctor's `replace-unconfirmed` check.
- A restore of the host no longer drops those checks: they start over against the restored document, and the 24 hours run from the first check after the restore.
- Your PCs now notice a host rebuilt from an older backup, even when the restore gives the memory an epoch number they already hold: their next `jobs tick` sends again what the backup lacks. doctor's `restore-epoch` check warns until then.
- `backsight retain reattribute` no longer sends again a session this PC found continued on another PC, which would erase that PC's part: it lists it as held.
- A Claude Code session open during `backsight connect` no longer retires memories on the old server: `memory_credit` refuses to report a memory as wrong or outdated (it would retire it on the old server), changes nothing, and asks for a restart of Claude Code. Its memory tools never send the new API key to the old server.
- Every write to the server checks that this PC has not joined another server since the command read its settings: `jobs maintain`, `retain purge-again`, `retain reattribute`, `forget` in every form, `verify`, `uninstall --purge-local`, and the purge records each tick syncs. A command stopped this way writes nothing and says why.
- `backsight doctor`'s `server` check no longer warns on a tailnet address: WireGuard encrypts the link, the API key included, so it is information. On a LAN address it still warns, and its fix now names the commands that move your PCs to a tailnet address. `backsight report` keeps hiding the server's project names in both cases.
- `backsight server token --out` and `backsight server expose --out` refuse a symbolic link or a directory as the token file (exit 2, nothing written); the file is replaced, never a link's target.
- Clearer messages: a `server expose` rolled back says the server started again on the restored `config.toml`; a `connect` stopped after it backed up this PC's own server names the archive instead of "nothing was changed"; `connect` and `connect --undo` say what an open session keeps until you restart Claude Code; doctor's detail for a private address not there yet keeps the server's own error.
- A price in `[llm]` that is not a finite number (`nan`, `inf`) is refused when `config.toml` is read.

**Changed output** (for scripts and agents that read it)
- doctor's `server` check is Info, not Warn, on a client whose server has a tailnet address.
- `backsight connect` puts a version difference in the patch only in a new `notes` field of `--json` (printed as `note`), no longer in `warnings`.
- `backsight stats --json` gains `server`: `host`, `last_ok`, `failing_since`, `breaker_open_until`, `notes_queued`, `sessions_waiting`, and, while writes are held, `other_server` and `held_since`.

## Install

```sh
curl -fsSL https://raw.githubusercontent.com/Barben360/backsight/main/scripts/install.sh | sh
backsight setup
```

Requirements as for v0.1.12-m6: Linux amd64, Docker with Compose v2 usable without `sudo`, Claude Code 2.1.309 or newer, an LLM provider key, about 6 GB of free disk. To join the memory of a PC already set up, install the binary the same way, then run `backsight connect --token-file <file>` instead of `backsight setup`. To put the memory server on another machine instead, run `backsight server install --ssh user@host` from a PC with OpenSSH's client; the host needs Linux on x86_64 or aarch64, Docker with Compose v2, `tar`, and `minisign` or OpenSSL 3. `backsight guide several-pcs` covers both.

## Known limits

- Tested on Linux amd64 only.
- A LAN address carries the API key in clear; a tailnet address encrypts it.
- The shared part of a session continued on two PCs may be stored twice.
- After a host restore, the PC that did not send a split session's last part may send the whole session again as its transcript holds it, shared part included: stored twice, never lost.
- A session part never confirmed after 24 hours is reported (doctor's `replace-unconfirmed`), not sent again automatically.
- Open Claude Code sessions keep the old server for their memory tools only, until you restart them. Prompt recall follows the new server at once, and the session is sent whole to the new server when it ends.
- A memory hidden on one PC still shows on your other PCs until their next fetch, up to about 6 hours later. When two PCs' clocks disagree, `forget --restore` on one may not win over a hiding made on another just before.
- The `Boost` line of `stats` counts prompts from v0.1.12-m6 on: over a window that starts before it, it understates how often the ranking changed what a prompt showed.
- `backsight feedback replay` compares only the recalls recorded from v0.1.10-m6 on: older ones lack the score it needs and are counted apart as not comparable.
- The list of similar memories Claude sees when it stores one can still hold a hidden observation.
- `recall.failure_pitfalls` stays off: a replay on real failed tool calls found its matches mostly unrelated.
- Project families stay off by default: a replay on real prompts showed no change yet.
