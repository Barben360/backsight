**Pre-release.** Linux amd64 is tested. Windows amd64 is tested in CI and, for this release's fixes, on a Windows 11 PC by a standard user: v0.1.21-m7 was installed there with `install.ps1`, set up, used from Claude Code sessions, restarted and checked; what that run found is fixed here. The Linux arm64 and macOS binaries are built but not tested.

Update from any earlier v0.1 with `backsight update apply`: it takes a verified backup first and rolls back if a step fails. Then restart Claude Code (or run `/reload-plugins`), so the memory tools and the skills use the new binary too. New install: see below. No server change, and no change to the metrics index.

## What changed

**Windows**

- `backsight jobs tick` and `jobs maintain` keep a log, `<project>-jobs-<name>.log` in the state directory's `logs` (10 MiB, the previous one as `.1`, keys replaced): a failed run used to leave no trace.
- Files that hold a key and go where you choose (`server token --out`, `server expose --out`, `server runtime fingerprint --keys`) are created readable by you, SYSTEM and Administrators only, before the key is written. They used to take their folder's permissions.
- Claude Code on Windows uses PowerShell as its main shell, and when it does not find Git Bash (a portable Git, or Git in a place of your own) it runs backsight's hooks in PowerShell too: the commands Claude runs then lack `BACKSIGHT_PROJECT` and `BACKSIGHT_SESSION`. Doctor's new `git-bash` check warns and gives the command that sets `CLAUDE_CODE_GIT_BASH_PATH`; `docs/windows.md` says what Claude Code needs.
- Uninstalling a second backsight wired to its own Claude Code profile no longer disables the plugin in your default profile (a Claude Code behaviour on Windows that backsight now undoes).
- A repeat `backsight client install` leaves an up-to-date shim in place, so a fresh install no longer reports an "earlier copy of the shim".
- Messages say how a file is kept private on Windows instead of "mode 0600", and setup's hint for saving the backup key no longer names `pass` there.

**Every platform**

- `backsight client install` enables backsight's plugin again when it is disabled in Claude Code, as doctor's fix for that warning says.
- `connect` works on a PC whose `config.toml` exists without a `secrets.toml`.
- `backsight uninstall` lists each Claude Code setting it changes once.
- `setup --help` says which answers `--non-interactive` cannot take by default (the provider and the consent).

## Install

On Linux:

```sh
curl -fsSL https://raw.githubusercontent.com/Barben360/backsight/main/scripts/install.sh | sh
backsight setup
```

On Windows x86_64, in PowerShell:

```powershell
powershell -ExecutionPolicy ByPass -c "irm https://raw.githubusercontent.com/Barben360/backsight/main/scripts/install.ps1 | iex"
backsight setup
```

Requirements as for v0.1.21-m7. On Windows, Claude Code must find Git Bash: if Git for Windows is portable or installed in a place of your own, set `CLAUDE_CODE_GIT_BASH_PATH` to its `bin\bash.exe` (doctor's `git-bash` check gives the command).

## Known limits

- Windows: WSL is not tested, and Windows on Arm has no binary. The native runtime is the only runtime there (`server runtime switch` is refused), it serves this PC only and has no web UI. The server starts with your logon, not at boot.
- On Windows, `backsight server status` keeps showing the server's last refusal while it is stopped, until a start passes the check.
- backsight's `.exe` files are not code-signed: SmartScreen or Smart App Control may warn about them. The install script checks the release signature before it runs anything.
- The dashboard pages are unstyled skeletons; their design comes in a later release.
- A new install reads "learning" for its first week, and some numbers read "too few" until enough prompts and turns accumulate.
- Extraction cost needs prices set under `[llm]` in the config file. The server reports token counts for all PCs together.
- On native, PostgreSQL is 18.1 with pgvector 0.8.5, where the Docker image runs 18.6 with 0.8.7; `backup verify` runs in the runtime that will restore.
- Claude cannot run `/reload-plugins`: after an update from the session, you type it.
- A LAN address carries the API key in clear; a tailnet address encrypts it.
- The shared part of a session continued on two PCs may be stored twice.
- A session part never confirmed after 24 hours is reported (doctor's `replace-unconfirmed`), not sent again automatically.
