**Pre-release.** Linux amd64 is tested; the Linux arm64, macOS and Windows binaries are built but not tested.

Update from any earlier v0.1 with `backsight update apply`: it takes a verified backup first and rolls back if a step fails. Then restart Claude Code (or run `/reload-plugins`). New install: see below. No migration and no server change: the new tool texts reach Claude through the regenerated plugin.

## What changed

**Memories Claude reports wrong or outdated**
- When a memory shown in a session proves false, or was true but no longer is, Claude reports it with `memory_credit` (`verdict: wrong` or `outdated`), giving the right fact and what in the session shows it (your words, a file, a command output). The instruction set moves to v8.
- backsight stores the right fact as a correction note, then retires the wrong memory. Nothing is deleted. A raw fact is invalidated on the server, so recall stops returning it. For an observation, Claude is first shown the facts it is drawn from and names the wrong ones, which are invalidated. An observation whose facts the server cannot list is marked hidden on this machine; the 15-minute job lifts the mark once the server rewrites or drops it.
- Claude can only report memories shown in the session, of the session's project, its transverse aliases or its linked projects, and at most 3 per session, the earlier turns of a resumed session included (`feedback.max_retirements`; `0` turns the reports off). A memory of another project, or one past that limit, is refused with nothing stored, and Claude hands you the `backsight forget <id>` command instead.
- Claude tells you which memory it retired and why. `backsight forget --restore <id>` undoes it: the fact is valid again, or the observation no longer hidden, and the report no longer counts against it.
- When the server refuses part of a retirement, Claude's answer names what was retired and what was not; the correction note is stored once.
- New `backsight memory stale` lists the memories worth a review, each once: shown at least 10 times and never used (`feedback.stale_shows`), observations hidden for 7 days and not rewritten since, and raw facts Claude reported. Each line carries the command that deals with it. It reads local files only and changes nothing in the memory; `--json` gives the same lists.
- `backsight stats` counts the reports by verdict (used, none, wrong, outdated, refused) and gains a `Retirements` line: the raw facts invalidated, the reports the server refused halfway, the observations hidden.
- Two new `[feedback]` settings in `config.toml`, none needed: `max_retirements` (3) and `stale_shows` (10). backsight never writes them; v0.1.8-m6 refuses a `config.toml` that has them, so remove them before going back to it.

**Install the memory server on another machine**
- `backsight server install --ssh user@host` installs the memory server on another Linux machine, a home server or a NAS for example, and joins it from this PC, in one command. It runs over your system `ssh` with your keys and `known_hosts`: backsight never writes `~/.ssh` and refuses an unknown or changed host key.
- It reads the host first and changes nothing there until you have seen the plan and agreed. It refuses a host it would break: one running another backsight version, a PC with Claude Code, or a client of another server. It picks the address your other PCs will use (the one your ssh reached, or `--private <ip>`; a LAN address carries the API key in clear and needs your confirmation).
- The host gets the release matching this PC's version, verified here and again on the host. The LLM key goes to `backsight secret set` there on its stdin, never on a command line. Then setup, `server expose` and `server token` run there; the token comes back over ssh, is never shown nor written on this PC, and `backsight connect` joins here.
- The host is never rolled back: every step can run again, so after a failure the same command goes on from where it stopped. `backsight setup --undo` on the host undoes its setup. `--plan` reads the host and shows the steps, changing nothing; `--json` streams each step's progress.
- `backsight server install --print-commands` prints the same steps as commands to run yourself, for a host you have no ssh access to. It runs nothing, and no line holds a secret.
- `backsight connect` now asks the acknowledgement of a host that extracts with a Claude subscription in its own plan, before it changes anything, and not again for a host of the same kind.
- After `backsight connect` switched servers, a `jobs tick` or a `retain backfill` begun before it sends nothing more to the old server, deletes nothing there and keeps its queued notes for the new one.
- `backsight paths --json` adds `server_role` and `server_mode`.

## Install

```sh
curl -fsSL https://raw.githubusercontent.com/Barben360/backsight/main/scripts/install.sh | sh
backsight setup
```

Requirements as for v0.1.8-m6: Linux amd64, Docker with Compose v2 usable without `sudo`, Claude Code 2.1.309 or newer, an LLM provider key, about 6 GB of free disk. To join the memory of a PC already set up, install the binary the same way, then run `backsight connect --token-file <file>` instead of `backsight setup`. To put the memory server on another machine instead, run `backsight server install --ssh user@host` from a PC with OpenSSH's client; the host needs Linux on x86_64 or aarch64, Docker with Compose v2, `tar`, and `minisign` or OpenSSL 3.

## Known limits

- Tested on Linux amd64 only. `backsight server install --ssh` is tested against simulated hosts, not yet over a real ssh connection.
- An observation marked hidden on this machine is still returned by recall in this release: only the record of what was shown and used knows the mark. Raw facts Claude reports are invalidated on the server and leave recall at once.
- The counts of which memories Claude used, and its reports, do not change which memories are recalled yet.
- Open Claude Code sessions keep the server they started with after `backsight connect` until you restart them.
- The record of which memories Claude used stays on each PC: PCs sharing a server do not share it yet.
- `recall.failure_pitfalls` stays off: a replay on real failed tool calls found its matches mostly unrelated.
- A search with many results may show no kinds on its last memories: the server caps the facts it returns with them.
- The new project rule is applied to subagent reports only; on the main conversation it is measured but not applied yet.
- Project families stay off by default: a replay on real prompts showed no change yet.
