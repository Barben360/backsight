**Pre-release.** Linux amd64 is tested; the Linux arm64, macOS and Windows binaries are built but not tested.

Update from any earlier v0.1 with `backsight update apply`: it takes a verified backup first and rolls back if a step fails. Then restart Claude Code (or run `/reload-plugins`). New install: see below. No migration and no server change.

## What changed

- `backsight doctor` no longer reports Claude Code's `tools-used` transcript records as unknown: they list the tools a session used and carry no conversation. Counts already recorded this week by an older version leave the warning as they age out of its 7-day window.

## Install

```sh
curl -fsSL https://raw.githubusercontent.com/Barben360/backsight/main/scripts/install.sh | sh
backsight setup
```

Requirements as for v0.1.6-m5: Linux amd64, Docker with Compose v2 usable without `sudo`, Claude Code 2.1.309 or newer, an LLM provider key, about 6 GB of free disk.

## Known limits

- Tested on Linux amd64 only.
- `recall.failure_pitfalls` stays off: a replay on real failed tool calls found its matches mostly unrelated.
- A search with many results may show no kinds on its last memories: the server caps the facts it returns with them.
- The new project rule is applied to subagent reports only; on the main conversation it is measured but not applied yet.
- Project families stay off by default: a replay on real prompts showed no change yet.

Report problems at https://github.com/Barben360/backsight/issues, after reading the diagnostic `backsight report` prints, or ask Claude `/backsight:doctor`. Report vulnerabilities privately, as https://github.com/Barben360/backsight/blob/main/SECURITY.md describes.
