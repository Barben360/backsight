**Pre-release.** Linux amd64 is tested; Windows amd64 is tested in CI and on a Windows 11 VM for the dashboard's Windows paths. The Linux arm64 and macOS binaries are built but not tested.

Update from any earlier v0.1 with `backsight update apply`: it takes a verified backup first and rolls back if a step fails. Then restart Claude Code and a running dashboard (Ctrl+C, then `backsight dashboard`). New install: see below.
- The server is unchanged (Hindsight 1.2.0): no server upgrade.
- The instruction set is unchanged (v16). The bank template and the plugin are unchanged.
- **The metrics index's schema changes** (one column: the sessions a `jobs tick` counted as waiting). `update apply` migrates it once the update is committed; an older version that runs afterwards keeps its own index file beside it.
- On Linux and macOS, `metrics.db` and `ledger.db` become readable by you alone, as every other file of backsight's state already was.

## What changed

The memory dashboard went through four independent reviews of the whole: does it do what it promises, do its tests catch a regression, is it safe, and are its numbers true on a real PC's data. This release fixes what they found.

**Numbers that were wrong** (https://github.com/Barben360/backsight/pull/254):
- **"Flowing: needs attention" with nothing waiting.** When sending was held (an extraction hold, a restore), a session with nothing left to send was still logged as "to retry", and no later line cleared it. The dashboard then said "0 waiting" in red with an item waiting for days, and counted that session as not sent. `jobs tick` now records which sessions it counts as waiting, and a session it no longer counts is read as sent; with the records of earlier versions, a tick that found no session waiting clears them. Such a session is no longer logged as "to retry". The backlog lines now say how long the oldest item has waited.
- **The verdict's lines followed the selected window.** At 30 days the Overview said "Cost ok, slowest prompts 2.1 s" under "last 7 days", where the 7-day figure was 1.3 s. The axis lines, the attention list and the copied summary now always show the last 7 days, like the verdict.
- **Time to recall said "ok" with too few sessions** in `stats` and its JSON, while the page said "too few". A figure judged on its slowest 1 in 20 now reads "too few" until it has 100 values, everywhere.
- **Extraction cost counted an extra day.** The server counts per UTC day, and a day straddling the window's start was counted whole: a custom 7-day window counted 8 days (on the developer's data, $19.17 where $15.38 belonged to the window). A UTC day now counts when its noon falls in the window, as the several-PC figures already did. `backsight stats [days]` asks the server for the same period and counts the same days, so it gives the dashboard's figures on every window (its layout is unchanged; on a rolling window its first day is now the server's partial one).
- **"Sessions sent" counted notes and subagent reports too.** The tile and the Pipeline page now say "items sent", and `stats pipeline` and the page add the breakdown (from sessions, notes, subagent reports); `pipeline.flow` gains `sessions`, `notes` and `subagent_reports` in its JSON.
- **The Days table counted a document sent twice as two.** "Sent" and "Failed" now count each document once per day.

**Safety** (https://github.com/Barben360/backsight/pull/255):
- **Windows are bounded.** A window typed in a URL or given to `stats --since/--until` had no length limit: one far-future `until` made a signed-in dashboard request use about 18 GB of memory, and year 1 gave an error page. A window is now at most 400 days, between 2000 and 2099: the CLI exits 2, the API answers 400, the page says why.
- **Commands to copy are quoted.** Project names and memory ids in the commands the dashboard and `stats --json` offer (`command` fields, Copy buttons) were pasted as they are: a project named with shell characters could run them. They are now quoted, for PowerShell on Windows and for sh elsewhere.
- **`metrics/published.json` no longer holds the server address and bank name**, only a hash of them; an earlier file is read as its hash, so nothing is sent again.
- `metrics.db`, `ledger.db` and their side files are created readable by you alone.

**Wording**:
- The Memories list is the whole feedback record, not the memories shown in the window: its help, page title, empty states and docs now say so, and `--sort`'s help names its real default (`shown`).
- With no memory server set up, the Overview, the copied summary and the Machines card say "no memory server set up" instead of "not answering".
- [docs/dashboard.md](../dashboard.md) lists every reason a figure can have no data, and [docs/commands.md](../commands.md) says which views wait during an update (those that must first build or migrate the index).

**Also**:
- On Windows, two sign-ins racing for one dashboard link could give the loser an error instead of "link already used" (https://github.com/Barben360/backsight/pull/251).
- Tests: new cases for the order of journal lines read after the last tick, a server pause that has ended, a clock set back, the agreement between `stats` and the views, month rotation and privacy checks on more fields (https://github.com/Barben360/backsight/pull/252); a migration test made deterministic on Windows (https://github.com/Barben360/backsight/pull/253).
- Dependencies: `modernc.org/sqlite` 1.61.1 and `spf13/pflag` 1.1.0 (https://github.com/Barben360/backsight/pull/245).
- The README's dashboard screenshots are redrawn.

## Install

On Linux:

```sh
curl -fsSL https://raw.githubusercontent.com/Barben360/backsight/main/scripts/install.sh | sh
backsight setup
```

On Windows x86_64, in PowerShell:

```powershell
powershell -ExecutionPolicy ByPass -c "irm https://raw.githubusercontent.com/Barben360/backsight/main/scripts/install.ps1 | iex"
backsight setup
```

Requirements as for v0.1.22-m7. On Windows, Claude Code must find Git Bash: if Git for Windows is portable or installed in a place of your own, set `CLAUDE_CODE_GIT_BASH_PATH` to its `bin\bash.exe` (doctor's `git-bash` check gives the command).

## Known limits

- Dashboard:
  - Version switches and settings changes are marked on a day's page and on Releases only, not on every chart.
  - The custom window goes back 13 months, as far as this PC keeps its history.
  - Time to recall needs a few days of history, and 20 sessions before it shows times; it is judged (ok or watch) only from 100 sessions, and reads "too few" until then.
  - A window, custom or typed in a URL, can span at most 400 days, between 2000 and 2099.
  - Bank growth still counts a UTC day that straddles the window's start as a whole day.
  - Memory yield needs four weeks: a week counts 28 days after it ends.
  - On a window over 200 days, charts show no per-day values on hover, and "Show as a table" lists the latest 120 days.
  - A week that is not complete shows no count of new memories.
  - The project filter takes a typed name, not a pick from a list (the Projects page lists the names). The Projects list cannot be sorted. The context card names the session budget rather than showing its value.
- GPU reranker:
  - It needs the Docker runtime, on the server's PC.
  - Tested on one NVIDIA RTX A2000 (Linux) and one AMD Radeon 890M (Linux). Intel GPUs, macOS and Windows are not tested.
- Owner checks:
  - The short-lived native units created during install, start and restore are not checked.
  - On Windows, when neither `schtasks` nor the task's file can be read, the task is driven as before.
- `retain resend-failed`: it does not cover notes and sub-agent reports sent while extraction failed (the queue drops them once sent). A transcript rewritten or moved after its worktree was deleted loses the project recorded for those turns, so the session is then filed by today's rules.
- The metrics index: an index already in write-ahead mode whose folder no longer allows it fails its writes until the state directory is back on a local disk. `stats days` reads a year of prompts with no index for it (about 0.1 s locally).
- Import: a file the server keeps rejecting holds that folder's next files until it passes. The last tick before a cap can overshoot it by what was already in flight. A file deleted from the folder stays in the memory until `import purge`.
- Windows:
  - WSL is not tested, and Windows on Arm has no binary.
  - The native runtime is the only runtime there (`server runtime switch` is refused). It serves this PC only, has no web UI, and starts with your logon, not at boot.
  - `backsight server status` keeps showing the server's last refusal while it is stopped, until a start passes the check.
  - backsight's `.exe` files are not code-signed: SmartScreen or Smart App Control may warn about them. The install script checks the release signature before it runs anything.
- A new install reads "learning" for its first week, and some numbers read "too few" until enough prompts and turns accumulate.
- Extraction cost needs a price: the built-in table's, or one set under `[llm]` in the config file for another model (doctor's `price` check says when none is known). The server reports token counts for all PCs together.
- On native, PostgreSQL is 18.1 with pgvector 0.8.5, where the Docker image runs 18.6 with 0.8.7; `backup verify` runs in the runtime that will restore.
- On Windows, the commands the dashboard and `stats --json` offer to copy are quoted for PowerShell; run through Git Bash, a name holding an apostrophe comes out without it.
- Claude cannot run `/reload-plugins`: after an update from the session, you type it.
- A LAN address carries the API key in clear; a tailnet address encrypts it.
- The shared part of a session continued on two PCs may be stored twice.
- Several PCs: a PC sends its figures once a UTC day, up to the day before, so another PC's today is not in all PCs until the next day; the others' figures are fetched every 6 hours. A PC counts in a window by the noon (UTC) of each of its days. The other PCs send no project, session or memory: Projects, Sessions and Memories stay this PC's, and a project filter does not narrow the others (`other PCs: not filtered`). The verdict stays this PC's. Speed across PCs is a range from time buckets, never an exact time, and the PCs' figures are trusted as sent: nothing signs them.
- The feedback database:
  - The ledger lookup's speed is measured on Linux only: Windows has no bench yet.
  - After a rollback to an older version and an update again, the counts that version added catch up at the first tick.
  - In a rare race during an update or a rollback, an older version can leave one tick's shows out of its `ledger.json`; this version's next tick counts them.

Report problems at https://github.com/Barben360/backsight/issues, after reading the diagnostic `backsight report` prints, or ask Claude `/backsight:doctor`. Report vulnerabilities privately, as https://github.com/Barben360/backsight/blob/main/SECURITY.md describes.
