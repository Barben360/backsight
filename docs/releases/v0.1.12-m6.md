**Pre-release.** Linux amd64 is tested; the Linux arm64, macOS and Windows binaries are built but not tested.

Update from any earlier v0.1 with `backsight update apply`: it takes a verified backup first and rolls back if a step fails. Then restart Claude Code (or run `/reload-plugins`), so `memory_search` uses the new binary too. New install: see below. No migration and no server change.

## What changed

**The record of which memories helped: fixes**
- A damaged record (`ledger.json`) no longer stays an error until you run `backsight feedback rebuild`: the next 15-minute job (`jobs tick`) keeps a copy of the damaged file next to it (`ledger.json.corrupt-<time>`) and rebuilds the record from the journal. Recall meanwhile ranks as if the record were empty.
- The check at the end of a turn and the limit of 3 retirements per session read the journal from the session's start, not the last 62 days at every call. A session started by an older version still reads 62 days.
- A journal line goes to the month file of the moment it records, not of the moment it is written.
- A reply with no word to compare (an empty reply, "OK.", "👍") no longer raises the "credited a memory the reply does not echo" flag.
- Past 50 memory texts kept for that comparison, the ones shown longest ago go first.
- A memory settled twice (after a lock broken by mistake) counts once.

**Reports, import, replay, stats**
- `memory_credit` refuses a `wrong` or `outdated` report while another server answers at the address this PC joined, as `backsight forget` does: nothing is stored or retired.
- The one-off import of your earlier history is marked complete only after a run in which the server answered, so a run while the server is down no longer ends the import early. The tick line says when it waits for the server.
- `backsight feedback replay` judges a change of sign on the exact values, not on the rounded ones it prints.
- `backsight stats` has a new `Boost` line: among the prompts and `memory_search` calls that showed memories, how many showed other ones because of the ranking by use. Its `Ledger` line separates the memories settled live from those imported from your earlier history. `--json` carries both.

**PCs sharing one server**
- A change of `feedback.miss_half_life_days` or `feedback.credit_half_life_days`, and a machine reaching 30 days of silence, now take effect on the other machines' counts at the next 15-minute job, not up to 6 hours later. No network is needed for it.
- `backsight uninstall --purge-local` first deletes this machine's copy of its counts from the server's control bank (5 seconds at most; when it fails, uninstall goes on and says so, and the other machines ignore that copy after 30 days). `--plan` lists it.

## Install

```sh
curl -fsSL https://raw.githubusercontent.com/Barben360/backsight/main/scripts/install.sh | sh
backsight setup
```

Requirements as for v0.1.11-m6: Linux amd64, Docker with Compose v2 usable without `sudo`, Claude Code 2.1.309 or newer, an LLM provider key, about 6 GB of free disk. To join the memory of a PC already set up, install the binary the same way, then run `backsight connect --token-file <file>` instead of `backsight setup`. To put the memory server on another machine instead, run `backsight server install --ssh user@host` from a PC with OpenSSH's client; the host needs Linux on x86_64 or aarch64, Docker with Compose v2, `tar`, and `minisign` or OpenSSL 3.

## Known limits

- Tested on Linux amd64 only. `backsight server install --ssh` is tested against simulated hosts, not yet over a real ssh connection.
- The `Boost` line of `stats` counts prompts from this version on: over a window that starts before the update, it understates how often the ranking changed what a prompt showed.
- Going back to v0.1.11-m6: it cannot read the new file of other machines' counts and ranks with this machine's counts alone until its next fetch, up to 6 hours.
- A memory hidden on one PC still shows on your other PCs until their next fetch, up to about 6 hours later. When two PCs' clocks disagree, `forget --restore` on one may not win over a hiding made on another just before.
- `backsight feedback replay` compares only the recalls recorded from v0.1.10-m6 on: older ones lack the score it needs and are counted apart as not comparable.
- The list of similar memories Claude sees when it stores one can still hold a hidden observation.
- Open Claude Code sessions keep the server they started with after `backsight connect` until you restart them.
- `recall.failure_pitfalls` stays off: a replay on real failed tool calls found its matches mostly unrelated.
- Project families stay off by default: a replay on real prompts showed no change yet.
