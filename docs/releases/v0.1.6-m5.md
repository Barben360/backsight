**Pre-release.** Linux amd64 is tested; the Linux arm64, macOS and Windows binaries are built but not tested.

Update from any earlier v0.1 with `backsight update apply`: it takes a verified backup first and rolls back if a step fails. Then restart Claude Code (or run `/reload-plugins`). New install: see below. No migration and no server change: the new texts, skill and hook reach Claude through the regenerated plugin.

## What changed

**Finding the right memory for what you are looking for**
- `memory_search` and `backsight search` show the kinds of each memory after its date, for example `[pitfall, state]`, and `subagent` when some of its facts came from a subagent's report. They come in the same call to the server, so a search is not slower. The JSON output gains `kinds` and `subagent`; the memories added to your prompts are unchanged.
- Claude is told how to search: a topic then an intent word (`docker compose subnet pitfall`), never a kind word alone, one query per angle, a date or version for a question about time. It searches before a risky or irreversible action (pitfalls and corrections), before design work (decisions) and before asking you a preference (conventions), and skips trivial edits and facts it already found.

**Keeping the memory current**
- When work ships (a PR merged, an issue closed, a root cause found) or a recalled memory proves wrong, Claude stores one dated fact that names the old claim, so the memory replaces it instead of keeping both.
- Claude states facts, never "a memory was stored or retrieved".
- A subagent's final report is kept in memory: it is now told to give findings with their cause, decisions with their reason and what was delivered where, without progress chatter.
- `/backsight:memory-retro` reads the project's recent git history, searches the memory topic by topic for what it already holds, also keeps rejected alternatives and open questions, asks which recalled memory proved wrong, and proposes (never applies) moving lasting rules into your CLAUDE.md, a `.claude/rules` file or a hook.

**Pitfalls when a tool fails (off by default)**
- New setting `recall.failure_pitfalls`: when a tool call fails, backsight searches the memory for that failure and hands Claude up to 2 memories that match it closely, once per kind of error and session. It stays off until it is shown to help. An older backsight refuses a `config.toml` that sets it: remove the line before installing an older version.

## Install

```sh
curl -fsSL https://raw.githubusercontent.com/Barben360/backsight/main/scripts/install.sh | sh
backsight setup
```

Requirements as for v0.1.5-m5: Linux amd64, Docker with Compose v2 usable without `sudo`, Claude Code 2.1.309 or newer, an LLM provider key, about 6 GB of free disk.

## Known limits

- Tested on Linux amd64 only.
- A search with many results may show no kinds on its last memories: the server caps the facts it returns with them.
- With "recent" briefings, a subagent now gets shorter briefing lines (100 characters each) to leave room for the report guidance.
- The new project rule is applied to subagent reports only; on the main conversation it is measured but not applied yet.
- Project families stay off by default: a replay on real prompts showed no change yet.

Report problems at https://github.com/Barben360/backsight/issues, after reading the diagnostic `backsight report` prints, or ask Claude `/backsight:doctor`. Report vulnerabilities privately, as https://github.com/Barben360/backsight/blob/main/SECURITY.md describes.
