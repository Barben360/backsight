**Pre-release.** Linux amd64 is tested; the Linux arm64, macOS and Windows binaries are built but not tested.

Update from any earlier v0.1 with `backsight update apply`: it takes a verified backup first and rolls back if a step fails. Then restart Claude Code (or run `/reload-plugins`), so `memory_search` uses the new binary too. New install: see below. No migration and no server change.

## What changed

**Recall learns from what Claude used**
- Recall now ranks memories with what this machine counted: a memory Claude often reports using rises, one often shown near the top and left unused sinks. The move is small and bounded: by default at most +0.075 or −0.025 added to its score. A memory with nothing counted keeps its score, and counts fade (misses lose half their weight in 90 days, uses in a year), so a recent use matters more than an old one. It applies to the memories recalled at each prompt, the write gate, the recall after a failed tool call, `memory_search` and `backsight search`.
- The floors on the server's score (`recall.min_score`, `recall.global_min_score`) apply first: the boost reorders what passed them and never lets a memory under them in. `memory_search`'s `min_score` and `backsight search --min-score` see the boosted score. `backsight search --json` gives each hit's `boost` and the rank it would have had without it.
- An observation hidden after Claude reported it wrong or outdated now disappears from recall on this machine, from the next prompt on, without waiting for the 15-minute job.
- When the record cannot be read, recall goes on as before, without boost and without hiding. With `feedback.enabled = false` nothing changes.
- The README shows, in a chart for each GitHub theme, how the boost moves with the share of shows Claude credits: a memory credited one time in ten stays where the server's reranker put it.
- Three new `[feedback]` settings in `config.toml`, none needed: `boost_weight` (0.1, how far the counts move a memory; `0` turns the boost off but still skips hidden memories), `prior_credits` (3.0) and `prior_misses` (9.0), the uses and misses every memory starts with. backsight never writes them; v0.1.9-m6 refuses a `config.toml` that has them, so remove them before going back to it.

**Earlier history counts too**
- The first maintenance run after the upgrade (`jobs tick`, every 15 minutes) adds to the counts what earlier versions left: each time a memory was shown, from this machine's telemetry and the Claude Code transcripts still on disk, and a credit for a turn whose reply cited memory and that showed exactly one memory (from telemetry only: a transcript does not name the memories injected with a prompt). It never counts a miss. It spends at most a minute per run and goes on at the next one until it is done; its progress shows on the tick's line.
- `backsight feedback import` does it at once. `--plan` counts per source and writes nothing; `--since <YYYY-MM-DD>` narrows it. Imported counts are kept apart from live ones, nothing is counted twice, and memories the server no longer holds are dropped. One import runs at a time: exit 20 while another one runs, exit 10 while feedback is off.
- `backsight feedback rebuild --no-import` recomputes the counts without what the import added.

**Measure a change before making it**
- `backsight feedback replay --set key=value` decides every memory shown on this machine again, once with the current settings and once with the change, and compares them: how many memories' boost turns negative or positive, the 10 that move most, and how many recalls would change their hits or only their order. It reads only and changes nothing. The keys are `boost_weight`, `prior_credits`, `prior_misses`, `confident_rank`, `miss_half_life_days` and `credit_half_life_days`. `--set boost_weight=0`, for instance, counts the recalls the boost reorders.

**Fixed**
- After `backsight feedback rebuild`, the next count applied again the reports and hidings made since the previous count: a memory reported wrong or outdated counted twice. It counts once.

## Install

```sh
curl -fsSL https://raw.githubusercontent.com/Barben360/backsight/main/scripts/install.sh | sh
backsight setup
```

Requirements as for v0.1.9-m6: Linux amd64, Docker with Compose v2 usable without `sudo`, Claude Code 2.1.309 or newer, an LLM provider key, about 6 GB of free disk. To join the memory of a PC already set up, install the binary the same way, then run `backsight connect --token-file <file>` instead of `backsight setup`. To put the memory server on another machine instead, run `backsight server install --ssh user@host` from a PC with OpenSSH's client; the host needs Linux on x86_64 or aarch64, Docker with Compose v2, `tar`, and `minisign` or OpenSSL 3.

## Known limits

- Tested on Linux amd64 only. `backsight server install --ssh` is tested against simulated hosts, not yet over a real ssh connection.
- `backsight feedback replay` compares only the recalls recorded from this version on: older ones lack the score it needs and are counted apart as not comparable. It can only reorder the memories a recall kept, so a change of hits shows only for a recall that kept more memories than `recall.prompt_hits`.
- The list of similar memories Claude sees when it stores one can still hold a hidden observation.
- The record of which memories Claude used stays on each PC: PCs sharing a server do not share it yet, so each ranks with its own counts.
- Open Claude Code sessions keep the server they started with after `backsight connect` until you restart them.
- `recall.failure_pitfalls` stays off: a replay on real failed tool calls found its matches mostly unrelated.
- A search with many results may show no kinds on its last memories: the server caps the facts it returns with them.
- The new project rule is applied to subagent reports only; on the main conversation it is measured but not applied yet.
- Project families stay off by default: a replay on real prompts showed no change yet.
