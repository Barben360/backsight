**Pre-release.** Linux amd64 is tested; the Linux arm64, macOS and Windows binaries are built but not tested.

Update from any earlier v0.1 with `backsight update apply`: it takes a verified backup first and rolls back if a step fails. Then restart Claude Code (or run `/reload-plugins`), so the memory tools and the skills use the new binary too. New install: see below. No migration and no server change.

## What changed

**Update backsight from a Claude Code session**

- The session line that announces a release now names the version you run, the new one, and both ways to update: `⬆️ backsight 0.1.15-m6 → 0.1.16-m6 · update here: /backsight:update · or in a terminal: backsight update apply`. When several releases are newer, it says how many: `(3 newer)`. It still shows no release notes, which are not signed.
- New skill `/backsight:update`: Claude tells you the installed and new versions and what changes, runs `backsight update apply --plan` and reports its steps, and installs only once you agree; Claude Code asks you to approve the install command each time. Claude relays the outcome, then asks you to type `/reload-plugins`. `backsight guide update#from-a-claude-code-session` describes it.
- `/backsight:doctor` and `/backsight:memory` now leave updates to `/backsight:update`.

**Changed output** (for scripts and agents that read it)
- The instruction set is v10 (telemetry's `v` field).

## Install

```sh
curl -fsSL https://raw.githubusercontent.com/Barben360/backsight/main/scripts/install.sh | sh
backsight setup
```

Requirements as for v0.1.14-m6: Linux amd64, Docker with Compose v2 usable without `sudo`, Claude Code 2.1.309 or newer, an LLM provider key, about 6 GB of free disk. To join the memory of a PC already set up, install the binary the same way, then run `backsight connect --token-file <file>` instead of `backsight setup`. To put the memory server on another machine instead, run `backsight server install --ssh user@host` from a PC with OpenSSH's client; the host needs Linux on x86_64 or aarch64, Docker with Compose v2, `tar`, and `minisign` or OpenSSL 3. `backsight guide several-pcs` covers both.

## Known limits

- Tested on Linux amd64 only.
- The session line comes from the running binary: the update to this release is still announced by the old line, and the new one appears from the next release on.
- Claude cannot run `/reload-plugins`: after an update from the session, you type it.
- Claude prints the lines itself: the end-of-turn check makes sure it reports the memories it used, not that it printed every line a tool handed back.
- With `feedback.enabled = false`, Claude still cites memories as `🧠 From memory (<project>) — …`, without ids.
- A LAN address carries the API key in clear; a tailnet address encrypts it.
- The shared part of a session continued on two PCs may be stored twice.
- A session part never confirmed after 24 hours is reported (doctor's `replace-unconfirmed`), not sent again automatically.
- Open Claude Code sessions keep the old server for their memory tools only after `backsight connect`, until you restart them.
- A memory hidden on one PC still shows on your other PCs until their next fetch, up to about 6 hours later. When two PCs' clocks disagree, `forget --restore` on one may not win over a hiding made on another just before.
- `backsight feedback replay` compares only the recalls recorded from v0.1.10-m6 on: older ones lack the score it needs and are counted apart as not comparable.

Report problems at https://github.com/Barben360/backsight/issues, after reading the diagnostic `backsight report` prints, or ask Claude `/backsight:doctor`. Report vulnerabilities privately, as https://github.com/Barben360/backsight/blob/main/SECURITY.md describes.
