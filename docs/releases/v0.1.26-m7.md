**Pre-release.** Linux amd64 is tested; Windows amd64 is tested in CI, with no new run on a Windows PC for this release. The Linux arm64 and macOS binaries are built but not tested.

Update from any earlier v0.1 with `backsight update apply`: it takes a verified backup first and rolls back if a step fails. Then restart Claude Code and a running dashboard (Ctrl+C, then `backsight dashboard`). New install: see below.
- With the Docker runtime, the server image is unchanged.
- With the native runtime, the update runs a server upgrade, which rebuilds the server's Python environment from the new lock. The memory is unavailable for a few minutes.
- The metrics index gains tables for the new local record (an additive migration). An older binary keeps working with its own index file.
- The instruction set is unchanged (v12).

## What changed

- **A GPU reranker** (https://github.com/Barben360/backsight/pull/169): the new page `backsight guide gpu-reranker` explains how to run the reranker on your GPU:
  - what to install, for NVIDIA (Text Embeddings Inference) or AMD and Intel (llama.cpp on Vulkan);
  - the service to add to the server's `compose.override.yaml`;
  - how to check it works and how to go back to the CPU.

  Measured: search went from up to 2.9 s to 0.11–0.28 s on an NVIDIA RTX A2000, and from 0.72–0.88 s to 0.33–0.39 s on an AMD Radeon 890M. backsight writes nothing for you: setup's pre-flight and doctor's `gpu` check point to the page when they find a GPU on a Docker server. Doctor reports a reranker set in the override as yours. An agent can follow the page and ask before it installs anything.
- **One install no longer drives another's server** (https://github.com/Barben360/backsight/issues/144): backsight named its Docker Compose project, systemd units, Windows task and supervisor after `server.project` alone. A second backsight home with the same name could restart, stop or delete the first install's server. Commands that change the server now check which install owns it, and refuse with exit 20 (`nothing was changed:`) when another install that is still in place does. Doctor's new `compose-owner` and `native-owner` checks name that install. A home you moved or renamed takes its server over at the next start (https://github.com/Barben360/backsight/pull/157, https://github.com/Barben360/backsight/pull/164).
- **Native runtime: newer Python packages with security fixes** (https://github.com/Barben360/backsight/pull/165): the native server's lock takes authlib 1.9.1, dnspython 2.9.0, fastmcp 3.4.11, OpenTelemetry 1.45.1 and pyasn1 0.6.5 ahead of the Hindsight image, which has no newer release yet. Each package and its reason are listed in `internal/server/nativelock/overrides.txt`. The Docker runtime still runs the image's versions.
- **A longer record for the dashboard** (https://github.com/Barben360/backsight/pull/166): the daily job now keeps, under `metrics/` in the state directory:
  - the server's daily counts and its history past what the server keeps;
  - each doctor run's check statuses;
  - where each memory came from;
  - the counts of each complete `memory scan`.

  These records hold ids, numbers and fixed words only, never a memory's text, a prompt, a path or a key. They only read the server and stay on this PC (see `docs/privacy.md`, "The local record"). No new dashboard page yet: memory yield needs a few weeks of this history first.
- **Windows: an update no longer fails while another program holds the shim** (https://github.com/Barben360/backsight/issues/148): replacing `current.exe` failed when a virus scan or the program loader had it open, and the update rolled back. backsight now retries for up to 2 seconds.

## Install

On Linux:

```sh
curl -fsSL https://raw.githubusercontent.com/Barben360/backsight/main/scripts/install.sh | sh
backsight setup
```

On Windows x86_64, in PowerShell:

```powershell
powershell -ExecutionPolicy ByPass -c "irm https://raw.githubusercontent.com/Barben360/backsight/main/scripts/install.ps1 | iex"
backsight setup
```

Requirements as for v0.1.22-m7. On Windows, Claude Code must find Git Bash: if Git for Windows is portable or installed in a place of your own, set `CLAUDE_CODE_GIT_BASH_PATH` to its `bin\bash.exe` (doctor's `git-bash` check gives the command).

## Known limits

- GPU reranker:
  - It needs the Docker runtime, on the server's PC.
  - Tested on one NVIDIA RTX A2000 (Linux) and one AMD Radeon 890M (Linux). Intel GPUs, macOS and Windows are not tested.
- Owner checks:
  - The short-lived native units created during install, start and restore are not checked.
  - On Windows, when neither `schtasks` nor the task's file can be read, the task is driven as before.
- Native runtime: filelock 3.20.3 keeps two published advisories, because litellm requires a version below 4.0 and no fixed version exists below 4.0 (https://github.com/Barben360/backsight/issues/130).
- Import: a file the server keeps rejecting holds that folder's next files until it passes. The last tick before a cap can overshoot it by what was already in flight. A file deleted from the folder stays in the memory until `import purge`.
- `retain resend-failed` does not cover notes and sub-agent reports sent while extraction failed: the queue drops them once sent.
- Windows:
  - WSL is not tested, and Windows on Arm has no binary.
  - The native runtime is the only runtime there (`server runtime switch` is refused). It serves this PC only, has no web UI, and starts with your logon, not at boot.
  - `backsight server status` keeps showing the server's last refusal while it is stopped, until a start passes the check.
  - backsight's `.exe` files are not code-signed: SmartScreen or Smart App Control may warn about them. The install script checks the release signature before it runs anything.
- Dashboard: the project filter takes a typed name, not a pick from a list (the Projects page lists the names). The Projects list cannot be sorted. The context card names the session budget rather than showing its value.
- A new install reads "learning" for its first week, and some numbers read "too few" until enough prompts and turns accumulate.
- Extraction cost needs prices set under `[llm]` in the config file. The server reports token counts for all PCs together.
- On native, PostgreSQL is 18.1 with pgvector 0.8.5, where the Docker image runs 18.6 with 0.8.7; `backup verify` runs in the runtime that will restore.
- Claude cannot run `/reload-plugins`: after an update from the session, you type it.
- A LAN address carries the API key in clear; a tailnet address encrypts it.
- The shared part of a session continued on two PCs may be stored twice.

Report problems at https://github.com/Barben360/backsight/issues, after reading the diagnostic `backsight report` prints, or ask Claude `/backsight:doctor`. Report vulnerabilities privately, as https://github.com/Barben360/backsight/blob/main/SECURITY.md describes.
