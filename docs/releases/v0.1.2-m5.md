**Pre-release.** A fix release of v0.1.1-m5. Linux amd64 is tested; the Linux arm64, macOS and Windows binaries are built but not tested.

Update from v0.1.1-m5 or v0.1.0-m5 with `backsight update apply`: it takes a verified backup first and rolls back if a step fails. New install: see below.

## What changed

**Setup**
- On a machine without a systemd user session (a container, WSL without systemd, a shell opened with `su` or `sudo`), setup now asks before writing anything: it names `--answer scheduler=off`, says what stops without a scheduler (sending sessions every 15 minutes, the daily maintenance and backup) and the commands to run by hand, or suggests logging in as that user directly. It used to stop halfway with an error a rerun could not fix.
- `backsight setup --resume --answer scheduler=off` continues where setup stopped, without asking for consent again. Any other changed answer still asks.
- Scheduler entries left by a failed attempt are removed, and doctor reports the scheduler as off instead of ok.

**Doctor**
- Claude Code's Artifact records in transcripts are no longer counted as unknown. The warning fades within a week, as the older counts age out.
- The shared-pool noise warning suggests the subagent cleanup only while there is something left for it to remove.

## Install

```sh
curl -fsSL https://raw.githubusercontent.com/Barben360/backsight/main/scripts/install.sh | sh
backsight setup
```

Requirements as for v0.1.1-m5: Linux amd64, Docker with Compose v2 usable without `sudo`, Claude Code 2.1.309 or newer, an LLM provider key, about 6 GB of free disk.

## Known limits

- Tested on Linux amd64 only.
- The new project rule is applied to subagent reports only; on the main conversation it is measured but not applied yet.
- Project families stay off by default: a replay on real prompts showed no change yet.
- A purge again costs a little LLM work on the server (consolidation); with the `claude-code` provider or a remote server it waits for `backsight retain purge-again --allow-subscription`.

Report problems at https://github.com/Barben360/backsight/issues, after reading the diagnostic `backsight report` prints. Report vulnerabilities privately, as https://github.com/Barben360/backsight/blob/main/SECURITY.md describes.
