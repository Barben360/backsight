# Commands

Every backsight command, grouped by use. `backsight <command> --help` shows the same flags with their defaults. Words you may not know are in the [glossary](glossary.md); `config.toml` keys are in [configuration.md](configuration.md).

## Conventions

- `--json` (every command): print one JSON envelope `{schema_version, command, ok, data | error}` instead of text. Coding agents use it.
- `--plan`: show what the command would do, changing nothing. Commands that change configuration, your files or the server's setup have it. Data operations do not: `secret set`, `backup create`, `store`, `forget <id>` and `retain flush` do what you asked; `retain backfill --plan`, `retain reattribute --plan` and `forget --project --plan` preview the larger ones.
- `--non-interactive`: never prompt; when an answer or a secret is missing, exit 10 and say what is needed.
- `--answer id=value` (repeatable) or `--answers-file <file>`: answers for commands that ask questions (`setup`, `uninstall`). Never secrets.

## Exit codes

| Code | Meaning |
|---|---|
| `0` | done |
| `2` | invalid invocation: unknown command, flag, argument or answer |
| `10` | you must act: answer a question, set a secret, run a command; the output says what, and how to resume |
| `20` | blocked by the machine (Docker not running, a lock held, a check failed); nothing was changed, or a rollback failed |
| `30` | failed and rolled back: the machine is as it was before |
| `40` | partly done and resumable: rerun the command named in the output |

## Install and wiring

| Command | Does |
|---|---|
| `backsight setup` | Sets up everything: server, bank, Claude Code wiring, jobs, verify, backfill offer. Flags: `--plan`, `--questions` (list the questions), `--answer`, `--answers-file`, `--non-interactive`, `--resume`, `--reconfigure` (at a terminal, ask every question again), `--config-dir <dir>` (another Claude Code profile), `--role server` (a host without Claude Code that only holds the memory for your other PCs: the Claude Code steps are skipped; see [install](install.md#a-server-only-host)), `--runtime native` (the server from PyPI under two systemd user units instead of Docker, on Linux x86_64, for this PC only: the answer `runtime`, kept by `--resume`; its pre-flight checks the systemd user session, lingering, the API port and 3.5 GB instead of Docker; refused with `--role server` and over an install already on Docker, exit 2; see [the native runtime](native-runtime.md)). |
| `backsight connect` | Joins the memory of another PC ([several PCs](several-pcs.md)): its server, with the connection token its host gave out (`backsight server token --out <file>` there). The token holds the API key, so it is read from a file (`--token-file <file>`) or from stdin (`--token -`, a hidden prompt at a terminal), never from the command line: a token given as a value or an argument is refused without being shown, and as it is then in your shell history, the message says to rotate the key on the host (`backsight server token --rotate`). connect first checks the server, reading only: it answers, accepts the key, holds the token's bank and has the token's server id (exit 20 otherwise, nothing changed; a public IP address is refused, exit 2); it warns when the server's Hindsight differs from this backsight's pin, and never refuses for it. Then it shows what it will change: `config.toml` (`server.url`, `server.bank`, `server.mode = "remote"`, and the host's provider, model and prices in `[llm]` for cost estimates, never a key), the `api_key` secret, and the server's id in `state.json`. A PC that was the client of another server starts its sends over on the new one: its session cursors, sent-index and split sessions move to `connect/<time>/` in the state directory (with `meta.json`, the state they went with), and each session then sends what the new server does not hold. It asks to go ahead at a terminal; without one, `--answer consent=yes` (exit 10 until then). It writes under the maintenance lock, once the sends already running and a restore-epoch reconcile (`jobs tick` catching up with a restored server) have ended (one still running after 2 minutes: exit 20, nothing changed); a send that began before connect sends nothing after it, and the next one goes to the new server. While an update did not finish, connect refuses (exit 20, nothing changed). If writing `config.toml` or the key fails, it puts back what it had changed and exits 30 (20 when that fails too: the message says what is left and where `meta.json` is); if only recording the server's id fails, it exits 40 with the command that finishes it. Then it runs `backsight setup`'s client steps (Claude Code wiring, retention, scheduler, verify, the backfill offer priced with the host's LLM; nothing about the provider or backups, which are the host's; a host that extracts with its Claude subscription extracts this PC's sessions on it too, so its caveat is asked by connect itself, in its plan, before anything changes: at a terminal after the plan, without one `--answer ack_subscription=yes` (exit 10 until then, nothing changed; `--plan` lists it; a PC that already accepted it for the same kind of host is not asked again), with setup's other answers (`--answer`, `--answers-file`, `--non-interactive`, `--config-dir <dir>`); if one stops, `backsight setup --resume` goes on. It never deletes the token file: it says to. Until restarted, an open Claude Code session recalls from the new server (hooks read the config on each run), but its memory tools keep the old one, and write nothing to it. `--plan` checks the server and shows the plan, changing nothing. A server-only host does not connect. A PC that runs its own server can join a shared one: a token of its own server is refused (exit 2, it is already connected). The plan then adds what leaving its server means: its past sessions are offered again to the new server (counted and priced as the backfill offer), the saved notes of its bank that no transcript left on this PC holds are counted (they stay in its old bank only), and its server is backed up, the archive verified, then stopped (its data and backups are kept). Its server must answer (exit 20 otherwise, nothing changed). A backup that fails or does not verify stops connect before anything changes but a backup identity a first backup generated (exit 20, the archive kept). Its `config.toml` and `secrets.toml` as they were are kept with the moved cursors in `connect/<time>/` (mode 0600, `meta.json` saying `mode` `local`), and if a later write fails, the server is started again with the rest put back (exit 30). |
| `backsight connect --undo` | Points a PC that joined a shared server from its own server back at it: under the maintenance lock, once the sends already running and a restore-epoch reconcile have ended (as connect waits), its sends to the shared server (cursors, sent-index, split sessions) move to `connect/<time>-shared/` in the state directory, then the `config.toml`, `secrets.toml`, cursors, sent-index and state that the newest such `connect` kept come back, and the shared server's id is forgotten; then it runs `backsight server start`. If the start fails, it exits 40 with `backsight server start` to finish (the switch stays done). While an update did not finish, it refuses (exit 20, nothing changed). A PC that had no server of its own before connect has nothing to go back to (exit 2): `backsight uninstall` removes the client. Until restarted, an open Claude Code session recalls from the new server (hooks read the config on each run), but its memory tools keep the old one, and write nothing to it. `--plan` shows what it would put back, changing nothing. |
| `backsight setup --undo` | Reverses setup; keeps config, secrets and the memory. `--plan`; `--force` restores files edited since. |
| `backsight verify` | Runs every hook and the memory tools as Claude Code would, then a store-and-recall round trip in a scratch bank. `--no-round-trip` skips the round trip (no LLM call); `--config-dir <dir>`. `--live` checks the real pipeline instead, read-only: this machine's latest settled session reached the server (every document of it: one per project its records belong to, `conversation:<session>` and `conversation:<session>@<project>`) and an observation was consolidated from it (exit 0 pass, 40 not yet, 20 failed with a fix). A session copied to another PC and continued there passes: a document whose later segments another PC sent (its `machine_id` differs from this PC's) counts as this PC's part reached, and the check names it (`continued on another PC: <documents>`, `continued_elsewhere` in `--json`); a later segment this PC wrote, or one without a `machine_id`, still fails. |
| `backsight client install` | Wires Claude Code: the plugin and its permission rule. Also makes `~/.local/bin/backsight` (a link to the shim) when nothing is there, and sends this version's bank template when the bank was given another one. `--plan`. |
| `backsight client retention` | Keeps Claude Code transcripts 3650 days; `--days N` sets another value, `--keep` stops managing it. `--plan`. |
| `backsight client retire` | Unwires another Hindsight integration from Claude Code. `--plan`. |
| `backsight client config plan` | Shows backsight's pending edits to Claude Code's files. |
| `backsight client config apply` | Applies them (a copy of each file is kept first). |
| `backsight client config restore [<run>]` | Puts Claude Code's files back as they were before a run (default: the last). `--plan`, `--force`. |
| `backsight uninstall` | Removes backsight from this machine. With `--purge-local`, it first deletes this machine's shared counts from the server it joined (5 s at most, never failing the uninstall). See [uninstall.md](uninstall.md). |
| `backsight paths` | Shows where backsight keeps its binaries, config and state; `--json` adds `server_role` and `server_mode` once a config exists. |
| `backsight version` | Prints the version; `--json` adds the release keys and the pinned Hindsight image. `--licenses` prints the license texts and notices of the third-party code in the binary (also `THIRD_PARTY_LICENSES` in every release archive). |

## Secrets

| Command | Does |
|---|---|
| `backsight secret list` | Shows which secrets are set, never their values. |
| `backsight secret set <name>` | Sets one, read at a prompt without echo, from a pipe, `--from-env VAR` or `--from-file FILE`. |

## Memory

| Command | Does |
|---|---|
| `backsight search <query>...` | Searches the memory, up to 4 short keyword queries. `--all`, `--project <name>`, `--limit N`, `--min-score X`. |
| `backsight read <id>` | Shows one memory with the facts it was built from. |
| `backsight store --kind <kind> <text>` | Stores one durable fact in the current project. `--project <name>`; `--project transverse` for a user-wide rule (required in the home directory). |
| `backsight forget <id>` | Retires a memory (reversible with `--restore`, which also undoes a retirement Claude reported); `--purge --yes` deletes it with its source facts and documents. Either way its counts of times shown and used are dropped at the next `jobs tick`. |
| `backsight forget --project <name>` | Retires every raw fact of a project in the configured bank (each reversible with `backsight forget <id> --restore`); `--purge` deletes its documents and observations for good. `--source <s>` keeps to the facts of one source (`chat`, `subagent`, `note`) and the observations drawn from them. `--plan` lists the documents and counts; the write needs `--answer confirm_project=<name>`. |
| `backsight memory scan` | Lists stored memories that look like they hold a secret, with the purge command for each. |
| `backsight memory notes` | Lists the notes stored recently (by Claude, `store` or `/backsight:remember`), newest first, with project, session and time. `--days N` (7), `--limit N` (20), `--project <name>`. |
| `backsight memory stale` | Lists the memories worth a review, each once, from this machine's record of what was shown and used: shown at least `feedback.stale_shows` times (10) and never used, counting only the shows recorded live (earlier history imported by `feedback import` never counts a miss, so its shows do not count here); observations hidden after Claude reported them, which the server has not rewritten in 7 days; raw facts Claude reported wrong or outdated (already invalidated). Each line gives the short id, the times shown, when it was last shown and the command that moves it on: `backsight forget <id>` for a memory never used; `backsight forget --restore <id>` for a hidden one, which shows it again (`backsight forget <id>` retires it for good once the server lists its source facts); `backsight forget <id> --purge` for a reported fact, which alone only lists what deleting it for good would remove (adding `--yes` deletes it). `backsight forget --restore <id>` undoes a retirement. Local files only; the memory is not changed. |
| `backsight ask <question>` | The server's LLM answers over many memories (costs tokens). `--all` for the whole memory. |
| `backsight projects` | Lists projects with their memory counts and last activity. |
| `backsight pause` / `backsight resume` | Stops or restarts recording this session; `--project` for the whole project (`--plan` shows the config change); `--session <id>`. |
| `backsight why` | Shows the last memories the hooks injected and why. `--last N`, `--session <id>`. |
| `backsight stats [days]` | Usage over the last days (default 7), the memories Claude reported used, wrong or outdated and what those reports retired included; its `Ledger` line counts apart the memories shown that settled live and those imported from earlier history, its `Boost` line, among the prompts and `memory_search` calls that showed memories, how many showed other ones because of the ranking by use; `--since`/`--until` for a fixed window. Its `Server` line is what this PC last recorded (at each recall and each `jobs tick`), never a call to the server, so it shows while the server is down, and it can say `silent` before doctor's `server-reach` warns (after an hour) or still say it until the next recall or tick once the server is back: `answering (last answer <age> ago)`, `silent since <time> (<age>)` with whether recall is paused and the notes and sessions waiting on this PC, `a different server answers at <host> … : writes held` with the same counts while another server answers at a client's joined address (`other_server` and `held_since` in `--json`), or `not recorded yet`; on a client it names the server's host (`server` in `--json`). |
| `backsight stats index` | Shows the local metrics index (a SQLite file in the state directory, built from the telemetry and feedback journal files): its file, size and schema, when it last ingested and how far it is behind the files, the lines it skipped and why (last 30 days), the side files of newer indexes and the corrupt file set aside, and a note when the folder is a network or synced one (the index then runs without its write-ahead log). Reads only: it never builds, migrates or ingests, and works during an update, on an index a newer backsight migrated and on a corrupt one. `--json` for the same fields. |
| `backsight stats index rebuild [--plan] [--yes]` | Builds the index again from the files on disk and swaps it in; nothing else reads the index meanwhile. Months whose files are gone cannot come back: `--plan` lists them with their row counts and writes nothing, and the rebuild needs `--yes` when there are any (or when the old index cannot be read). It refuses while the dashboard or a `jobs tick` holds the index (exit 20, the old index kept) and while an update is being applied (exit 20), and lifts the stop that follows a second automatic recovery within a day. Progress goes to stderr. |
| `backsight feedback log` | The timeline of one memory (`--id <id>`, its first 8 characters are enough) or one session (`--session <id>`, its first 8 characters are enough, by default `$BACKSIGHT_SESSION`), oldest first: each time it was shown (where, at which rank), credited and settled, with the turn number; with `--id`, its counts at the end, credits and misses faded to now. `--since <date>`. Reads only. |
| `backsight feedback rebuild` | Recomputes every memory's counts of times shown, credited and missed from the journal (losing `ledger.json` costs nothing). `--plan` shows the totals and how many memories would be added, dropped or changed, writing nothing. `--no-import` leaves out what `feedback import` added. Exit 20 while a `jobs tick` is settling: run it again. |
| `backsight feedback import` | Adds what earlier versions left to the counts: from this machine's telemetry and the Claude Code transcripts still on disk, each time a memory was shown (by a prompt or a `memory_search`), and, from telemetry only, a credit for a turn whose reply cited memory and that showed exactly one memory (a transcript does not name the memories injected with a prompt, so its turns count as shows only). It never counts a miss: earlier replies rarely said which memory they used. Imported counts are kept apart from live ones, a show already imported or already in the live record is not counted again, and memories the server no longer holds are dropped (asked read-only, for at most 30 seconds; ids it could not be asked about are kept and named). Writes ids, ranks and times only, never text. `--since <YYYY-MM-DD>`; `--plan` counts per source (sessions, shows, credits, ids dropped) and writes nothing. The `jobs tick` after an upgrade runs it on its own, a minute at a time, until one run goes through everything with the server answering; this command does it at once. A run that cannot reach the server (down, or another server at the address) keeps the ids it could not ask about and leaves the import open: the next run that reaches the server ends it. A run with `--since` leaves the earlier history to the tick (or to a run without `--since`). One import runs at a time: exit 20 while another one (yours or the tick's) is running. Exit 10 while feedback is off. |
| `backsight feedback replay` | Measures a change of the feedback parameters on this machine's history: decides every time a memory was shown again, once with the current parameters and once with `--set key=value` (repeatable; keys `boost_weight`, `prior_credits`, `prior_misses`, `confident_rank`, `miss_half_life_days`, `credit_half_life_days`, each with a value `config.toml` accepts), and compares the two: how many memories' boost turns negative or positive (judged on the boost itself, not on the 4 decimals shown), the 10 whose boost moves most (short id, before, after), and how many journaled recalls (a prompt's, the write gate's, a `memory_search`) would change their hits (for a prompt, its first `recall.prompt_hits`) or only their order. It orders the hits the record kept, by score without the boost plus each boost, so a change of hits shows only for a recall that kept more hits than `recall.prompt_hits`; recalls recorded before this version, without that score, are not comparable and counted apart. Reads only; nothing in `config.toml` changes. Exit 2 for an unknown key or a refused value. |

## Sending sessions

| Command | Does |
|---|---|
| `backsight retain flush` | Sends the unsent turns of every session now, without the 30-minute wait. `--session <id>`. |
| `backsight retain backfill` | Imports past sessions within a spending cap, and says on stderr how far it is after each session. `--plan`, `--since YYYY-MM-DD`, `--project <name>`, `--max-cost X`, `--max-tokens N`, `--allow-subscription`, `--projects-dir <dir>`. `--status` shows the progress of the queued import, sending nothing and without the server. |
| `backsight retain retry-quarantine` | Gives quarantined sessions and notes another try. `--session <id>`, `--notes`. |
| `backsight retain purge-again` | Purges again every purged document the server holds again: an older backsight, or any client unaware of purges, appended to its id and the server recreated it. Each goes as with `forget --purge` (the observations of its facts, its facts, the document, then the briefing pages of its projects); the turns written after the purge that it holds go again to the session's current document at the next send (a turn written before the purge never does, even if its send was still queued). `jobs tick` and `jobs maintain` do it on their own, except with the `claude-code` provider or a server this machine does not run (`server.mode = "remote"`): then this command does it, with `--allow-subscription` (the server consolidates again after a purge). A document an append is queued for waits for it. `--plan` lists them and changes nothing. A second run does nothing. Exit 10 while the consent is needed, 20 under maintenance or when the server cannot be read, 40 when one waits (run it again later). |
| `backsight retain reattribute` | Files the memory already sent under the projects today's rules give. A document whose whole content belongs to another project is moved in place, with no extraction (the server then consolidates the moved memories again, a few LLM calls each), at most 50 per run. A session whose documents mix projects is sent again per project, at its extraction cost, only with `--answer resend=yes`. It waits for a verified backup, a server with nothing queued and no restore or update in progress; sessions still being sent, quarantined, continued on another machine or whose directories are gone are left alone. With the `claude-code` provider it needs `--allow-subscription`. A second run does nothing. `--plan` lists the moves and the cost. Exit 10 while an answer is needed, 20 when it is not safe now, 40 when a write failed (run it again). |

## Server

| Command | Does |
|---|---|
| `backsight server status` | Shows the server's containers and API health. |
| `backsight server start` | Renders the Compose files if needed and starts the server. `--plan`. |
| `backsight server stop` | Stops the server; containers and data are kept. `--plan`. |
| `backsight server install` | Installs and starts the server alone (setup does it). `--plan`, `--provider`, `--model`, `--base-url`, `--api-port`, `--ui-port`. Once the server is healthy and its bank applied, its `server-id` step gives the server an id, which every connection token carries; if the server does not answer that step, install warns `server id: …` and goes on (memory works on this machine without it), and the id is written by `backsight server install` again or by the first connection token made (`backsight server expose --private <ip>`, or `backsight server token` once the server is exposed). `backsight server install --ssh user@host` installs the memory server on another machine instead, a Linux host without Claude Code, and joins it from this PC; it runs over your system `ssh`, with your keys and `known_hosts`: backsight never writes `~/.ssh`, and the destination's host key is checked strictly (an unknown or changed one is refused, never accepted), but a `ProxyJump` hop in your ssh config runs with that config's own options. In order: it reads the host (read-only), refuses one it would break (another backsight version there, a PC with Claude Code, a client of another server), picks the address the other PCs will use (the one your ssh reached, or `--private <ip>`; a LAN address needs `--answer cleartext_lan=yes`), shows the plan and asks (`--answer consent=yes` without a terminal), asks you to accept the terms of a Claude subscription when the host's provider is `claude-code` (`--answer ack_subscription=yes` without a terminal), reads the LLM key (`--llm-key-from-file <file>`, `--llm-key-from-env <var>`, a hidden prompt, or without a terminal the first line piped on stdin). Only then does it change the host: this PC copies the release matching its own version, verified here, and the host's `install.sh` verifies it again; the key goes to `backsight secret set llm_api_key` there on its stdin, never on a command line; then `backsight setup --role server`, `backsight server expose --private <ip>` and `backsight server token` run there. The token comes back over ssh and is never shown nor written on this PC; last, `backsight connect` runs here (at a terminal it shows its own plan and asks; declining it leaves the host installed and this PC as it was, exit 0 with connect skipped, and the same command joins later). With `--json`, each step streams a progress line on stderr as it starts and ends, and the host's own progress follows as `host:<step>`. `--answer` takes the host's setup answers (`provider`, `model`, `base_url`, `api_port`, `ui_port`, `project`, `backups`, `scheduler`) and this PC's (`retention`, `backfill`, `reference`); `--source <dir>` reads the release from a local directory; `--non-interactive` never prompts; `--config-dir` is this PC's Claude Code directory; `--plan` reads the host and shows the steps, changing nothing. Refused with exit 2, before any ssh: the new flags without `--ssh` or `--print-commands`; a target other than `user@host` or a host alias; a value the host's login shell could read otherwise than `sh` (a backslash, a `!`, a control character, or a leading `=` or `%`); a connection token in any argument; both key flags, or `--plan` with one; `cleartext_lan` other than `yes`, an unknown answer id, or a flag and an answer that disagree. Refused with exit 2 later, once the host was read and before it changes: a `--private` that is not a LAN or tailnet address, and an empty LLM key. The host is never rolled back: every step can run again, so after a failure the same command (the `resume` it prints) goes on from where it stopped; `backsight setup --undo` on the host undoes its setup. `backsight server install --print-commands` prints the same steps as commands to run yourself, for a host you have no ssh access to: it runs nothing and reads no config nor secret, and it refuses (exit 2) `--ssh`, `--plan`, `--source`, the key flags, `--non-interactive`, `--config-dir`, `--answer consent` (setup and connect ask at their own terminal), a token in any argument and a `--private` that is not a LAN or tailnet IP address (`--json` lists each command with where to run it, the host or this PC, and why). It takes `--provider`, `--model`, `--base-url`, `--api-port`, `--ui-port`, `--private <ip>` and `--answer`: the host's setup answers and `ack_subscription` go on the setup line, `cleartext_lan` on the expose line, and this PC's (`retention`, `backfill`, `reference`) on the connect line; with a LAN `--private` and no `cleartext_lan`, a comment before the expose line says the host will ask for it; the commands install the release matching this backsight on the host, set the LLM key at the host's own hidden prompt, set up, expose and write the token to a file you carry to this PC yourself (never through a chat), and `backsight connect --token-file` joins here; setup and connect show their plan and ask at their terminal. A development build has no release to name and is refused. |
| `backsight server render` | Writes the server's `compose.yaml` and `.env` from config and secrets. `--plan`. |
| `backsight server upgrade` | Moves the server to the version this binary pins, after a verified safety backup. `--plan`, `--allow-unordered`. |
| `backsight server runtime switch <docker\|native>` | Moves the memory to the other [runtime](native-runtime.md#switch-runtimes): checks the target and downloads what it runs (a failure changes nothing), then, under the maintenance lock, recalls up to 20 recent memories, stops the source's API, backs it up and verifies the archive in the target, stops the source (its data is kept), restores the archive into the target, compares the target's data with the source's (any difference fails), starts it, recalls the same memories again (a lower overlap is a warning, never a failure) and only then writes `server.runtime` to `config.toml`. Same URL, key and server id: no client does anything. Any failure or Ctrl-C before that stops the target and starts the source as it was, exit 20, the backup kept. Refused, nothing changed: when the source runs another Hindsight release than the one this backsight installs on the target (exit 20: run `backsight server upgrade` first; a switch never upgrades), on a client (exit 2), to native with `--role server` (exit 2), off Linux x86_64 or with a private exposure (exit 20), with lingering off (exit 10), to native when the shim the database unit runs belongs to an older backsight (exit 20), when `config.toml` or `secrets.toml` changed during the downloads (exit 20). Asks first at a terminal; else `--answer consent=yes` (without it, exit 10). `--plan`, `--non-interactive`, `--answer consent=yes`. |
| `backsight server runtime clean` | Deletes the server and data of the runtime switched from, kept since the switch: on Docker the database volume, the model cache, the containers and backsight's `compose.yaml` and `.env`; on native all of `server/native` (the database, the Python environments and the models, also what a failed switch downloaded there). Shows all of it with its size ("size unknown" when it cannot tell), asks, then deletes. The runtime in use and the backups are never touched; nothing there is "nothing to clean". Refused while a switch runs or was cut off. `--plan`, `--non-interactive`, `--answer consent=yes`. |
| `backsight server llm check` | Checks the extraction LLM on a fixed sample, storing nothing. |
| `backsight server expose` | Opens the server to your other PCs, or closes it again. `--private <ip>` publishes its API and UI on that address of this machine as well as on 127.0.0.1 (this PC keeps `server.url` on 127.0.0.1), sets `network.exposure = "private"` and `network.bind_ip` in `config.toml`, restarts the server and checks it answers on both; then it hands out the connection token as `server token` does (`--out <file>`, or a terminal; with neither, as with `--json` or a piped output, it says to run `backsight server token --out <file>`). The address must be a private address of this machine: the error lists the ones it has. A tailnet address (Tailscale: `100.x`, or `fd7a:115c:a1e0::/48`) keeps the API key encrypted; a LAN address carries it in clear, so the command exits 10 until it is rerun with `--answer cleartext_lan=yes`. On the [native runtime](native-runtime.md) `--private` is refused, exit 20, nothing written: native serves this PC only. `--loopback` publishes the server on 127.0.0.1 only again and removes `network.bind_ip`: other PCs can no longer connect. `--plan` shows the change to `config.toml` and to the server's files and changes nothing. If the server does not run healthy afterwards, `config.toml` is put back byte for byte and the server started on it again: the command exits 30, or 20 when the server did not start again on it or `config.toml` could not be put back (the message says which, and what to run). It holds the maintenance lock while it restarts the server (hooks queue, jobs skip). |
| `backsight server token` | Hands out the connection token another PC joins this server with: its address on the private network, the bank, the API key, the server's id and its LLM's prices. It holds the API key, so it goes to a terminal or, with `--out <file>`, to a file only you can read (mode 0600, an existing file replaced; a symlink or a directory there is refused, exit 2, nothing written); `--json` and a piped output need `--out`, and `--json` never shows it. It needs a server exposed on a private address (`network.exposure = "private"`) and running. `--rotate` gives the server a new API key first (a lost laptop): every token handed out before stops working; this PC follows (hooks and jobs read the key on each run, open Claude Code sessions at their next memory call), and every other PC joins again with the new token. `--rotate --plan` says what the rotation would do and changes nothing. If the server does not run healthy on the new key, the old key is put back and the server started on it again: the command exits 30 and the old token still works, or 20 when the server did not start again on the old key, or the old key could not be put back in `secrets.toml`, which then holds the new key, carried by no token (the message says which, and what to run). The rotation holds the maintenance lock while it restarts the server (hooks queue, jobs skip). |
| `backsight bank apply` | Creates the bank if needed and applies backsight's extraction settings, unless the bank was already given this version's. `--force` sends them anyway, over any edit made to them on the server. On a local server whose bank is still `claude-memory`, it runs `bank rename` first. Runs on the server's host only: a client refuses it, and its `client install` and `update apply` skip the bank (clients on other backsight versions would overwrite each other's settings). `--plan`. |
| `backsight bank rename` | Moves the banks of an install from before v0.1.4-m5 (`claude-memory`, `-docs`, `-control`) to `backsight`, `backsight-docs`, `backsight-control`, keeping every memory: it waits for the server's running operations (up to 10 minutes), dry-runs then runs Hindsight's own rename (`hindsight-admin rename-bank`, no LLM call) under the maintenance lock, keeps each old id as an alias of its bank so a client still using it keeps working, moves this machine's records (state.json, session cursors) and sets `server.bank`. If one bank cannot move, the ones before it are renamed back and nothing changes. The update to v0.1.4-m5 runs it (through `bank apply`), and `jobs maintain` tries again after its backup when the server was busy. A remote server is renamed on its host. `--plan`. |

A PC becomes a client with `backsight connect`. On a client (`server.mode = "remote"`), every command that manages the server (`server install` without `--ssh` or `--print-commands`, which concern another machine and so work on a client too, `render`, `start`, `stop`, `status`, `upgrade`, `token`, `expose`, `llm check`, `backup create`, `restore`, `uninstall --stop`, `uninstall --delete-data`) refuses and names the server's host and the command to run there. `backsight bank apply` and `backsight guide index` refuse too: the bank and the docs bank are the host's. `backsight jobs maintain` skips the backup on a client, and setup there generates no backup key.

## Backups and restore

| Command | Does |
|---|---|
| `backsight backup create` | Makes an encrypted backup now. |
| `backsight backup list` | Lists backups, newest first. |
| `backsight backup verify <file>` | Decrypts a backup, restores it into a throwaway database and compares counts. `--identity <file>`. |
| `backsight backup identity show` | Prints the key that decrypts your backups, alone on stdout, so it pipes into a password manager (`backsight backup identity show \| pass insert -m backsight/backup-identity`). Refused without any terminal (an agent) and with `--json`. |
| `backsight backup identity import [file]` | Stores a backup identity from a file or stdin. `--force` replaces another one. |
| `backsight restore <file>` | Restores a backup into the local server. `--plan`, `--identity <file>`, `--no-safety`, `--non-interactive`, `--answer other_banks=revert` (the server's banks without a control bank go back to the archive too). |

## Diagnostics

| Command | Does |
|---|---|
| `backsight doctor` | Checks the whole install, read-only; each problem comes with its fix. Among them, `server-reach` says when this PC's server last answered, and `replace-unconfirmed` warns when a session part this PC sent in the last 30 days was never confirmed on the server. On a host set up with `setup --role server`, the checks that look at Claude Code read `not a client: server-only host`. |
| `backsight report` | Prints a redacted diagnostic and links to search and file a GitHub issue. Sends nothing. |
| `backsight guide` | Lists these documents; `backsight guide <topic>` shows one (`<topic>#<section>` one section), `backsight guide search <question>` searches them: semantically on the server, with a keyword search when the server cannot answer (`--mode keyword` asks for it). |
| `backsight guide index [--plan]` | Indexes these documents into the server's docs bank (`<bank>-docs`, no LLM call). Setup and `update apply` run it, and `guide search` when the bank holds other docs. Several backsight versions can share the bank: each tags the sections it holds, and a section is deleted only when no version holds it. The bank keeps the last 5 versions, by the time each was first indexed (recorded in its `docs:_versions` document): an older version's tags are removed, and its sections no kept version holds are deleted. A `<bank>-docs` that backsight did not make (another name, or documents that are not its sections) is left as it is: `guide index` refuses and `guide search` uses its keyword search, saying why. `--plan` lists the documents it would create, resend, retag, untag, prune (losing only a dropped version's tag) and delete, and the versions it would drop. Runs on the server's host only: a client refuses it, and its setup and `update apply` skip the docs step. On a client, `guide search` never writes the docs bank: when the bank holds none of this version's docs, it uses its keyword search. The `/backsight:doctor` skill may run `guide` and `guide search` without asking, never `guide index`. |

Details: [troubleshooting.md](troubleshooting.md).

## Background jobs

The OS scheduler (systemd user timers on Linux) runs these; you rarely need them by hand.

| Command | Does |
|---|---|
| `backsight jobs tick` | Every 15 minutes: starts a server exposed on a private address once that address is on this machine again, if Docker could not start it before (see [troubleshooting](troubleshooting.md#after-a-reboot-the-server-was-down-for-a-while-private-exposure)); settles the record of which memories were shown and used into per-memory counts (local files only, so it runs even while the server is down; see [configuration](configuration.md#feedback-which-memories-claude-used)), and after an upgrade adds earlier history to those counts, a minute at a time until done (`backsight feedback import`); sends settled sessions and queued notes, paces the backfill, then looks among the documents created since its last look for a purged document an older client wrote again, and purges it again (`retain purge-again`). |
| `backsight jobs start tick` (or `maintain`) | Starts the job now through the OS scheduler, with its environment and log, without waiting for it. Setup runs it right after it queued your past sessions. |
| `backsight jobs maintain` | Daily: rotation of the local usage log, backup, then the in-place moves of `retain reattribute` (never a re-send, which costs extraction: doctor shows the ones waiting), the look at every purge tombstone for a document an older client wrote again (`retain purge-again`), update check (and update with `update.auto_apply`), doctor snapshot (it keeps the transverse pool's noise reading, so doctor sees it grow). |
| `backsight jobs install` | Installs the scheduler entries (setup does it). `--plan`. |
| `backsight jobs uninstall` | Removes them. `--plan`. |
| `backsight jobs refresh` | Rewrites entries whose template changed, without stopping a running job (updates do it). `--plan`. |
