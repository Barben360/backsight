# backsight — specification (draft v14, 2026-10-29)

> `backsight`: a self-hosted Hindsight memory for Claude Code. Binary, plugin and marketplace `backsight`, Go module `github.com/Barben360/backsight`, MIT [decided 0034].
> Tags: **[decided]** decision file by the author · **[agent]** decided by the agent under the author's delegation (2026-10-23: "if there are choices that can't be debated internally, present them at the end"), recorded in `decisions/`, open to veto · **[E#]** backed by `experiments/` · **[author]** needs the author (§20) · **[later]** out of v1.
> Glossary §21 · schemas Appendix A.

## 1. Purpose and success criteria

Give Claude Code a long-term memory across sessions and projects, self-hosted on the user's own Hindsight server, installed in minutes, safe to update and back up, that **measurably changes agent behaviour**: it searches before asking, reuses past decisions, avoids known pitfalls, and records what it learns.

v1 is done when:
1. **Onboarding**: a new user, alone or through a Claude Code agent, goes from nothing to a working memory with one bootstrap command and one `setup`; no file edited by hand; every step previewable (`--plan`) and undoable (`setup --undo`) (0004).
2. **Parity**: on the author's Linux machine the product replaces the reference stack (Python hooks, npm plugin, retro timer), with telemetry over two weeks after the M4 cut-over at least equal to the Python baseline (C12 metrics, Appendix A.4); the M2 replay is the earlier gate (0048).
5. **Time to value** (preview, 0048): median time from bootstrap to the first recalled memory ≤ 15 min (image download excluded); ≥ 4 of 5 preview installs finish without help.
3. **Harmlessness**: no hook can block or erase a prompt; the prompt hook's wall time is p95 ≤ 2.5 s on a local server (deadlines are safety nets, not targets); failures are silent for Claude and visible in `doctor` (0010, 0048).
4. **Recoverability**: a backup restores into a fresh stack and passes `backup verify`; a failed update rolls back automatically.

## 2. Principles

- **Deterministic first** (0008) [decided]: the binary detects, configures, merges, migrates, checks, backs up. LLM judgement only where it is the job — fact extraction and consolidation (Hindsight's server LLM) and the installing agent's contextual choices, always through binary commands with JSON output. **The binary itself calls no LLM.**
- **One Go binary** (0001), **Docker Compose** for third-party services (0011; a native runtime behind a server runtime interface comes in M7, 0070), **Claude Code only, one user per install, English facts and instructions (0039), Linux x86_64 first** (0007, 0010) [decided].
- **Suggest, never act outward** (0002, 0005) [decided]: no automatic issue; the binary never deletes memory on its own (only explicit user commands: `forget`, `forget --purge`, `uninstall --delete-data`, `restore`), with one measured, rule-based exception: `jobs maintain`'s sweep of status-only subagent reports, after the daily backup (§9.1, 0083 C3); the agent's one path is a reversible retirement on an explicit `memory_credit` verdict with evidence (0074 block 2, §7): a raw fact invalidated with its reason, never purged, told to the user, undone by `forget --restore`, at most `feedback.max_retirements` per session; no update applied without opt-in.
- **Facts over taste** [agent]: features are kept, tuned or cut on telemetry and experiments.

## 3. Architecture

```
 Client machine                                                 Server role (same machine or another)
 ┌───────────────────────────────────────────────┐             ┌────────────────────────────────────────────┐
 │ Claude Code                                    │             │ Docker Compose project (generated)          │
 │  plugin (generated local marketplace, §5)      │             │  hindsight  upstream image, pinned digest   │
 │   hooks ─exec─► backsight hook <event>  │──HTTP+key──►│    API 127.0.0.1:8888 · UI 127.0.0.1:9999   │
 │   MCP ─stdio──► backsight mcp           │             │  postgres+pgvector  named volume            │
 │   skills                                       │             │  compose.override.yaml  user-owned, kept    │
 │  Bash tool ───► backsight <command>     │             └────────────────────────────────────────────┘
 │ OS scheduler ─► jobs tick (15 min) · jobs maintain (daily)                       ▲ server commands run there
 └───────────────────────────────────────────────┘
```

- **Roles**: `client` (hooks, MCP, CLI, jobs) and `server` (compose project, bank config, backups) in one binary. Local mode = both on one machine. Remote mode §11.6.
- **Processes**: hooks are short processes behind a supervisor (§6.1); the MCP server lives as long as its Claude Code session; nothing else stays resident.
- **Jobs** [agent, 0025]: native OS scheduler entries (systemd user timers, launchd agents, Task Scheduler) call the shim, one lock per job: `jobs tick` every 15 min = settled-session retain and notes outbox flush, then the feedback steps (hidden-observation checks and, with `feedback.share_ledger`, the shared ledger: §9.1 control bank documents, 0074 block 4), and the briefing pages' reconcile once per binary version, floor and briefing request (§6.2, 0083 C2); `jobs maintain` daily = backup, update check, entity index refresh, telemetry rotation, doctor snapshot, the briefing pages' reconcile (0083 C2) and the subagent sweep (§9.1, 0083 C3).
- **Paths** [agent]: versions in `<data>/bin/<version>/`; stable shim `<data>/bin/current` (symlink; a copy on Windows) referenced by every generated file; `~/.local/bin/backsight` (or `%LOCALAPPDATA%\Programs\backsight\`) → shim, put on PATH by the bootstrap; config `<config>/config.toml`; secrets `<config>/secrets.toml` (0600, the only secret store in v1); state `<state>/`. `<data>/<config>/<state>` follow XDG, `~/Library/Application Support`, `%LOCALAPPDATA%`. Never `${CLAUDE_PLUGIN_DATA}` (deleted on uninstall, C05). Layouts: Appendix A.
- **Compose ownership**: the binary renders `compose.yaml` and `.env` from config + secrets (`server render`); users customise only `compose.override.yaml`, which Compose merges and the binary never touches (a user's own GPU service lives there, 0035).

## 4. Memory model [agent]

| Aspect | Rule |
|---|---|
| Bank | One per install, id in config, default `claude-memory`. Always a fresh bank: existing Hindsight data is never taken over; history comes from transcripts (0036, 0037). |
| Project tag | Every write carries exactly one `project:<name>`: `project` from the repository's `.backsight.toml` if set, else the basename of the git main worktree (worktree-aware, `$CLAUDE_PROJECT_DIR` fallback), else the directory name; `doctor` warns when one name is seen with two git remotes (0045). Transverse aliases (default `[".claude", "<home basename>"]`) mark sessions run outside repositories; the **first alias is canonical**: every transverse write is tagged `project:<first alias>` (one pool, so corrections merge); the others are read as transverse (a fresh bank never holds them as write tags). |
| Other tags | `source:chat|note|subagent`, `harness:claude-code` (continuity with the npm plugin) or `harness:codex` (0085: from the client's adapter, on segments, notes and subagent reports), `kind:decision|correction|convention|pitfall|state|lesson` — emitted by Hindsight from an entity-label group with `tag: true` on every strategy [E9], and set explicitly by `memory_store`. Subagent reports add `agent:<subagent_type>` (0071). Raw facts keep all tags; no other tag joins a scope (0071: an observation carries only its scope tag, so a tag added for search would split the pools). Item metadata is document-level (an append replaces it on every unit, E30 V2; since 0090 a session's later segments are documents of their own, `D#part<s>`, each with its own): constant values only (`entrypoint`, `agent_type`, ids). |
| Observation scopes | **Project only**: every write sends `observation_scopes: [["project:<name>"]]`; bank default `[["project:*"]]` covers writes made by other tools. One observation pool per project: no duplicates between writers, corrections rewrite the stale observation [E10, E11, E17]. Observations carry only the project tag. |
| Strategies | `conversation` (session retain), `document` (notes) and `subagent` (subagent reports, 0071 C5, E30 V5; 0071 C5's "a status-only report holds no fact" proved wrong, 875 facts from 1,274 stubs, so such reports are kept out by SubagentStop's gate and swept, §6.2 and §9.1, 0083 C3) carry the English-facts rule (0039) and the durability rules (durable, typed, absolute dates, exact identifiers, nothing for plans or hypotheses) [E17]. Shared with `import` (0081), the rules keep one fact per **delivered outcome** (a pull request merged with what it closes, a release published, a setting changed and where) and extract no **process steps** (commits made, pushes, branches created or deleted, rebases, CI runs and their status, pull requests opened or updated, waiting states); the `state` kind reads "A delivered outcome (merged, released or configured), and where." (0083 C6). No separate retro pass [E17]. |
| Reads | Recall and search use **observations**; raw facts are evidence (`memory_read`). While observations are not yet consolidated (backfill in progress) the client falls back to `world`/`experience` [E12]. |
| Corrections | A fact stored in the right project; consolidation rewrites the observation with history [E11]. **Limit**: a transverse rule ("never use X") does not rewrite a project observation saying the opposite; both can be recalled, and the guide tells the agent that user-wide rules win. Soft invalidation (`state: invalidated`, reversible) only through the user command `forget`. |
| Untagged observations | Prevented for every write that carries a project tag; `doctor` counts them (the source machine showed a residual 1-3 %/day of unknown cause under `combined`); fix = report upstream with `report`. No SQL repair in v1 (0036). |
| Language | **Facts always in English** [decided 0039, E19; E20: recall-neutral inside Hindsight]: every strategy text and bank mission starts with that rule, identifiers and quoted user wording kept verbatim [E7, E9, E17]. Models stay multilingual because prompts are searched raw. No language setting. |
| Read scopes | `project` (current + transverse) and `global` (whole bank) queried as **separate calls** so project memories cannot be crowded out; `related` (≤ 6 projects from the entity index, built lazily through `GET /entities?tags=project:<p>`) [E8]. Projects listed in the repository's `.backsight.toml` `related = [..]` (≤ 10) join the `project` call and count as near (no foreign floor, 0071 C3). Results merged by best score with a +0.05 boost for the current project, plus the **feedback boost** (0074 block 3) `k × ((credits + α) / (credits + misses + α + β) − α / (α + β))` (`feedback.boost_weight`, `prior_credits`, `prior_misses`; credits and misses decayed to now with their half-lives; a memory without a ledger entry gets exactly 0), read at each recall from the ledger plus the folded journal lines after its `journal_at` position (`feedback.Current`). With `feedback.share_ledger` (0074 block 4) each ranked id's entry first gains the other machines' credits and misses (each decayed to now) and their latest hiding from `feedback/shared-combined` (A.3: one file read, a binary search per id, no document parsed, never the network); a remote hiding applies unless this machine's `unhidden_at` is later. That view missing, unreadable, of another version, more than 30 days old or more than a day ahead: local counts alone, byte-identical. Floors on the server's reranker score (`recall.min_score`, `global_min_score`) apply before the boost and are unchanged; a floor on the merged score (`memory_search`'s and `search`'s `min_score`) sees the boosted score. Hidden observations are dropped from every recall path (prompt, gate, failure, `memory_search`, `search`; not `memory_store`'s similar list). Feedback off, or a ledger that cannot be read, of another schema or empty: no boost and no hiding, output byte-identical. Hits show their project. |
| Server | Hindsight **1.1.x**, digest pinned per release; 0.10.1 → 1.1.0 verified: fast migrations, identical recall on identical data [E2]. |

## 5. Claude Code and Codex integration [agent, E1, 0085]

- **Clients** (0085): one adapter per coding tool (`internal/harness`: home, install, hooks, MCP session, conversations, tool names, texts), Claude Code first and the default, Codex second (below). Every telemetry event and journal line carries `client` (`claude-code`, `codex`; absent = `claude-code`). A tool whose home is recorded at install (Codex) is read only once `client install` wired it, in that recorded home.
- The binary **generates a local marketplace** `<data>/marketplace/` with one plugin: `hooks/hooks.json` and `.mcp.json` in exec form pointing at the shim, skills, `version` = binary version, author and icon. `client install` runs `claude plugin marketplace add <dir>` then `claude plugin install <plugin>@<marketplace> --scope user`; updates regenerate the directory then `claude plugin marketplace update` + `claude plugin update`. No `command` source, no y/N, no PATH dependency [E1]. The hooks follow the config: `PostToolUseFailure` is registered only when `recall.failure_pitfalls = true` (the switch is part of the plugin's version hash, layout 6, so flipping it takes effect at the next `client install`; the drift check and doctor's `client` check name the switch when it is the only difference, and `verify` runs only the wired hooks; 0083 C9). Missing or too old `claude` CLI (minimum fixed in M1 CI) → exit 10 with the two commands printed.
- **Claude Code files are edited only by the config editor** [decided 0042]: pre-image, byte-level JSON patch, hash-checked write, `--plan`, undo (`client config plan|apply|restore`). User settings get `permissions.allow` for the three memory tools and, if accepted, `cleanupPeriodDays` (0041). `readOnlyHint` does not skip prompts [E15], and a prompt on every `memory_store` would defeat "records what it learns"; writes are redacted and only reach the user's own memory [agent, 0029].
- **CLAUDE.md**: not edited by default [E6]; `setup --claude-md` writes a marked block.
- **Tool names** are `mcp__plugin_<plugin>_<server>__<tool>`: marketplace and plugin `backsight`, MCP server `memory` → `mcp__plugin_backsight_memory__memory_search|memory_read|memory_store`, skills `/backsight:remember` etc. [0034]; a rename is a generated-file change. The gate and telemetry use PostToolUse, not name regexes over transcripts.
- **Drift check** at SessionStart (stat + hash, < 5 ms): plugin version, permission rule, shim target; mismatch → one banner line, `doctor`, `setup --repair`.
- **Exclusivity**: at the end of setup only one integration writes to the bank. During migration milestones the `components` flags (`read`, `write`; Appendix A.1) let the product run next to reference pieces not yet replaced.
- **Codex** (0085, as built): `<data>/codex-marketplace/` (marketplace `backsight`) holds two plugins: `backsight@backsight` (`.mcp.json` under the key **`backsight`**: the shim with `["mcp","--harness","codex"]`, `env_vars ["BACKSIGHT_HOME"]`; the skills, invoked `$backsight:<name>`) and `backsight-hooks@backsight` (its manifest, whose `version` hashes `hooks/hooks.json`, and that file). Each handler is one string, `"<shim>" hook --harness codex <event>` (`command` quoted for `sh`, `commandWindows` for `cmd /C`), with a `timeout`, no `args`. Tools are `mcp__backsight__memory_search|memory_read|memory_store|memory_credit` (Codex does not prefix plugin servers; a user server named `backsight` is refused by setup and `client install --codex` and warned by doctor). `client install --codex [--codex-home D]` (home: the flag, else a non-empty `$CODEX_HOME`, else `~/.codex`, recorded once in `state.json` `clients.codex`) refuses `codex` older than 0.167.0, runs `codex plugin marketplace add` and `codex plugin add` for each plugin missing, disabled or changed, and tells the user to trust the hooks in Codex's review (`/hooks`) when `backsight-hooks` was (re)added; backsight never writes a trust hash. Codex's `config.toml` is edited only through the config editor's rules (pre-image, journal, hash-checked write, undo): removing backsight's `[hooks.state."backsight@backsight:…"]`/`"backsight-hooks@backsight:…"` tables at uninstall, and `client codex-memories off|on` (Codex's own memories, offered off by setup). No approval key is written: the tools' hints suffice (§7). Drift at SessionStart compares Codex's recorded home, plugin version and shim; `update apply` runs the new binary's `client install --codex` when Codex is wired.

## 6. Hooks

### 6.1 Supervisor [agent, 0013]
`backsight hook <event>`: a parent reads stdin, re-executes the binary as a child with a hard deadline, **always exits 0**, prints the child's stdout only if the child exited 0 with valid hook JSON. Panic, Go fatal error (unrecoverable, exit 2), timeout or kill → nothing printed, one telemetry line. Hooks never wait on locks, never prompt; every network call has a total deadline, and inside it a connect bound of `min(3 s, timeout)` for name resolution plus the TCP connect, so a server that silently drops packets costs a prompt 3 s, not its whole budget (0075). Chaos tests inject panic, fatal error, hang and SIGKILL into every event.

## 7. MCP server [agent, 0021]

`backsight mcp` (stdio, `alwaysLoad: true`); `instructions` = the short guide (≤ 1 000 chars).

| Tool | Parameters | Does |
|---|---|---|
| `memory_search` | `queries` (1-4 short keyword queries), `projects?`, `scope?` (`auto`/`all`), `limit?`, `min_score?` | Recall on observations across scopes; hits grouped by project with id, date and age, each prefixed with its merged rank `#N` (the order before grouping, 0074), the feedback boost and hiding applied (§4; the ledger is read at each call, not at server start); the result ends with the credit ask (§8). After each search, with a current live record and an unpaused session, the MCP server journals a `recall` line (A.3) for the audit and `feedback replay`; a journal failure goes only to telemetry. |
| `memory_store` | `kind` (decision, correction, convention, pitfall, state, lesson), `text` (1-3 sentences, the why, absolute dates), `project?` (default current; a transverse alias for user-wide rules) | First recalls the most similar existing memory (one hit at `recall.store_similar_min_score`, default 0.8, the score after the feedback boost); only one that passes is returned (its text on one line, cut at 200 characters), and the Updated line names it (`replaces <id8>`); otherwise the reply is the stored line and the Saved line alone (0083 C4). The memory shown is journaled as a `store` show (§6.2 PostToolUse), so `memory_credit` accepts it with any verdict; the end-of-turn check leaves store shows out (a store asks for no declaration), they are never a miss, and the metrics keep them out of rate denominators. Then retains document `note:<uuid>` (strategy `document`, tags project + `source:note` + `kind:<kind>`, project-only scope) through the notes outbox. Refuses detected secrets (§13). |

### 9.1 Session retain [agent, 0018]

- **Settled retain** [E18b, 0031]: the transcript file is the durable log; the per-session cursor (byte offset + fingerprint of the consumed prefix) marks what was sent. Unsent turns are retained when the session settles: at SessionEnd, or by `jobs tick` when the last turn is ≥ 30 min old; sessions left open for long also send segments whose turns are ≥ 2 h old. **Appends wait** (0083 C1): a later segment of a conversation document this PC already wrote (an "append", sent since 0090 as a part of its own) is sent only when the rendered text pending over the documents it continues is ≥ `retain.append_min_chars` (default 30,000, the bank's `retain_chunk_size`; since 0090 the gate no longer prevents re-extraction, which parts avoid, but bounds the number of parts, each one retain operation and one more consolidation pass), or the oldest last send from this PC among them is ≥ `retain.append_max_wait` old (default 6 h; the turns still settled or long-open; a last send later than now, a clock set back, never holds), or the flush is forced (SessionEnd's `retain flush --session`, `retain flush`, backfill) or resyncs; 0 for either key turns the gate off. A session's first send, the first send to a new project document or to a purge's successor (`#2`), resync and reattribution, notes and subagent reports are never held; a failed or missing SessionEnd send goes out by the 6 h path at the latest. `retain waiting` names the reason `append_gate`. Settled extraction keeps far fewer overturned hypotheses than per-turn appends (1 vs 4-6 on a long debugging session) with equal coverage.
- **Protocol**: one document per session and project (0071 C2a): `conversation:<session_id>` for the session's home project, `conversation:<session_id>@<project>` for each other project, each with its own segments. Positions are per document; a mid-session directory outside any repository keeps the previous project, and a record inheriting an opted-out project stays out (INDEX "0071 C2a review rules"). Strategy `conversation` (chunk 30 000 chars). Segment 1 is the document `D` (the live id: `conversation:<sid>`, `@<project>`, a purge's `#<n>`); segment `s ≥ 2` is a document of its own, **`D#part<s>`**, without `update_mode` and without the `REF-ID` line, with the same strategy, context, tags and metadata (0090: Hindsight's `update_mode: append` retains the whole stored text again and re-extracts its tail chunk, 1,561 of 2,774 appended facts replacing deleted ones in 3 days). Documents an older build appended to stay as they are: an appended `D` holds segments 1…K and the session goes on at `D#part<K+1>`. `operation_id` = UUIDv5(bank, `D`, segment, content hash), over `D` and not the part's id, so a resend after a crash collapses server-side, across an update too. A flusher holds a per-session file lock (try-lock; stale after 10 min or dead pid), advances the cursor only on 2xx, keeps on timeout/429/5xx/503 (honours `Retry-After`), quarantines on other 4xx (`doctor`). Prefix fingerprint mismatch → one full replace. Cases ported from upstream `retain-cursor.test.ts`.
- **Formats, timing and errors in detail**: decision 0050 (E21 verified that an append replaces `document_metadata` and that a repeated `operation_id` collapses).
- **Identity and deduplication** [0038]: document `conversation:<session_id>` (same id as the reference npm plugin); each segment's `document_metadata` = `{last_uuid, records, segment, machine_id, binary_version}`. The server is the source of truth for what was sent: the client reads the session's position before every later segment that is not a resync and resumes after `last_uuid`. The position is the chain's end (0090): the last found of `D`, `D#part<seg(D)+1>`, `D#part<seg(D)+2>`…, `seg(D)` being `D`'s metadata segment, one missing part stepped over (parts may be stored out of order), two in a row ending the chain; before a send the read starts at the part of the cursor's last segment, falling back to `D`; resync, the restore reconcile and `retain reattribute` read from `D`; `verify --live` compares the chain's end and counts every part's facts. A tombstone of any member of a chain marks the chain purged (next segment to the successor, a cursor on it resynced, a pending replace dropped); the purge guard's listings match chains, and its look by id probes the two parts after each tombstoned chain. Every part sent is checked as segment 1 is (below; 0090 P2b): a part another PC's same-numbered part replaced, or one the server never stored (a hole the chain steps over), is sent again after the chain's end; `verify --live` fails on such a hole; doctor `queue-age` warns when the server's oldest queued retain is 6 h old and none completed in the last hour (these repairs and late purges wait for it; still completing: information). A document another PC moved is resynced once, this PC's segment numbered after the server's (cursor `split_bases`); a lag of its own segment is not a move. A segment 1 replaces its document: one another PC replaced is read back in `original_text` (with its parts') by a later tick, flush or backfill (never a hook) and the missing part sent again, numbered after the chain's end (cursor `replaces`; a restore (another epoch number, or the same number with another `restored_at`) keeps the mark and starts its looks over against the restored document; given up 24 h after the send, or after the first run that found the restore, `replace_unconfirmed`; 0075). A session continued on two PCs is sent from both ("never lose", 0073; the shared part may be stored twice; doctor `split-session`); otherwise a session is stored once (after a host restore, the PC that did not send the document's last part re-sends the session as its transcript holds it, shared part included, by design). Every write, the briefing page's creation, `forget`, verify's round trip and uninstall's ledger delete included (reads never), first checks the sends generation (none once `connect` raised it after the process read its config) and the `server_id` (none while another server answers at the address). `--resume` appends to the same transcript (verified 2026-10-24): the cursor sends only the new turns. ### 9.3 Detector [agent]

**End-of-turn check** (0074 block 1; replaces "no Stop blocking in v1"): Stop for the main agent, SubagentStop for each subagent (by `agent_id`). Local only, within the Stop budget. - `declared`: a `credit` line of the turn and agent; `blocked`: the block above.
- `undeclared`: asked once already (`stop_hook_active`, or a `blocked` line of the turn), or `stop_check = "cited"` and the reply carries no 🧠 citation while the turn only injected memories (no `search` or `read` show).
- `check_skipped`: `stop_check = "off"`, a machine-message turn, a headless or SDK session (`privacy.skip_entrypoints` on the parent entrypoint), or a journal that cannot be read (fails open, never blocks).
- Nothing is checked or journaled in a paused session, with `feedback.enabled = false`, before any turn pointer, or for a turn that showed nothing. A briefing after resume or clear, and a background subagent outliving its parent's turn, are not asked.
- **Honesty flags** (audit only): `none_with_overlap` (declared none, the reply repeats a shown memory's words) and `credit_without_overlap` (a credited memory the reply does not echo).
- Telemetry `credit_check {outcome, shown, flags, after_block}`; `after_block` marks a `declared` or `undeclared` turn blocked earlier, so `stats` splits declarations before Stop from those after a block.

5. **Bank** (`bank apply`): missions, strategies `conversation`/`document` with language and durability rules, entity labels incl. `kind`, `default_observation_scopes`; additive, applied-config hash recorded.
6. **Provider check**: `POST /memories/dry-run-extract` on a fixed sample must return ≥ 1 well-formed fact in English (proves auth, model, structured output and language end to end).
7. **Client** (`client install`): plugin (`claude plugin …`), then the config editor (0042): permission rule, retention; scheduler entries. Where `codex` answers (0085; its home from `setup --codex-home D`, else `$CODEX_HOME`, else `~/.codex`), a `tools` question first (`claude-code|codex|both`; default `both` when Claude Code is found too, else `codex`): Claude Code's questions and steps run only when it is picked; Codex gets a pre-flight (version), a `codex` step (`client install --codex`) after `retention`, then `codex_import` (`import --from codex`, asked when its stores hold unsent files; default no, recommended yes) and `codex_memories` (asked only when Codex's memories are on; default and recommended off) after `import`. Reference pieces are retired after verify passes (`client retire`, §11.5, 0064).
8. **Verify**: `verify` (every hook through the supervisor with a synthetic stdin, MCP handshake) + a retain/recall round trip on a scratch document, deleted afterwards; `verify --codex` when Codex is wired (Codex-shaped events, the server as `mcp --harness codex`, one call naming its session in `_meta` and one refused; with both tools a single round trip).
9. **Backfill** (offered, with its `--plan` numbers; runs in the background through `jobs tick`) [0037]; it covers each tool picked or already wired, counted per tool in the question (`retain backfill --queue --tools codex|both`; Claude Code alone keeps today's command).
10. **Summary**: what was done, `restart_required`, `try_first`, how to undo.
Every touched user file goes through the config editor (0042): pre-image in `<state>/pre-images/<ts>/`, byte-level patch, atomic temp + rename only if the hash is unchanged (re-read and re-apply up to 3 times), plan output limited to edited paths (never a whole `~/.claude.json`).

### 11.4 Maintenance lock
`<state>/maintenance.lock` (owner pid, command, since) is taken by update, backup and restore; hooks then only append to outboxes, jobs skip, MCP writes queue. A stale lock (dead owner) is reported, never stolen silently.

### 11.5 Replacing a reference install [0036]
`setup` detects reference pieces (npm plugin hooks and MCP server, Python hooks, retro timer, CLAUDE.md memory section, research C13) and **retires the client pieces** through the config editor (0042: hook groups and `enabledPlugins` in settings.json, `mcpServers` in `~/.claude.json`, pre-images kept, `setup --undo` restores them) once backsight's own client is installed and verify passed. The user's CLAUDE.md memory section is personal text and stays as it is (0064). The old server and its data are left untouched and running: the user stops it once it is no longer needed as a fallback (on the author's machine, after M5 proves backsight's backups and restore). doctor lists the reference files left on disk (retro script, disabled timer). History reaches the new bank through backfill (§9.1). No database takeover, no guarded SQL in v1 (0030 superseded).

### 11.6 Remote server [agent, 0024, 0073]
- **Roles**: `server.role = "both"` (default) or `"server"`, a host without a coding tool (`setup --role server`: no `claude` or `codex` pre-flight, client install, retention or backfill; the scheduler entries `jobs maintain` needs are kept; doctor reports the client checks as "not a client"). A client of another PC's server is `server.mode = "remote"`. A client PC may run Claude Code, Codex or both (0085): `connect` and `server install --ssh` take `--codex-home` and the `tools`, `codex_memories`, `codex_import` answers.
- **Exposure**: `loopback` (default), or `server expose --private <ip> [--plan]`: a LAN or tailnet address, published on 127.0.0.1 and `bind_ip` (the host's own `server.url` stays loopback); API and UI keys mandatory; a public address refused; an address outside tailnet ranges needs `--answer cleartext_lan=yes` after a warning that the key travels unencrypted; for an `http` address that is not loopback, doctor's `server` check reads Info on a tailnet and Warn otherwise, its fix a re-expose on a tailnet address (no TLS proxy yet). `server expose --loopback` closes it again. A private address that comes up after Docker (Tailscale or DHCP at boot) leaves the server down: `jobs tick` and SessionStart start it again once the address is there (SessionStart looks at most every 5 min; after a start that does not bring it up, both wait 15 min, doubling up to 6 h, the count restarting after a reboot on Linux), never during a restore or a held server lock.
- **Token**: `bst1.` + base64url JSON `{url, bank, api_key, ui_url, hindsight_version, server_id, llm}` (`llm`: provider, model and prices, never a key, for a client's cost estimate). `server token [--out F] [--rotate [--plan]]` writes it to a 0600 file or a terminal only (an `--out` that is a symlink or not a regular file is refused, exit 2, nothing written; `server expose --out` too); `--rotate` gives the server a new API key first, and every earlier token stops working. It is read from stdin or a file, never an argument, and redaction masks it.
- **`server_id`**: a random id in the control bank (`backsight:server`), kept by a restore; a fresh install without restore gets a new one. A client that finds another id (or none) at its address holds every write until the joined server answers there again, or `connect` runs (doctor `server-id`, banner, `stats`).
- **Joining**: `connect --token - | --token-file F [--plan]` checks the server, shows its plan, writes address, bank, `server.mode = "remote"`, key and `server_id`, then runs setup's client steps; a PC with its own server stops it after a verified backup (data kept) and re-sends its transcripts. `connect --undo` returns to its own server. Version skew never refuses: connect gives a patch-only difference as a note (JSON `notes`), any other as a warning; doctor's `version-skew` grades them Info and Warn. `bank apply`, `guide index` and server lifecycle commands run on the host only; a client refuses, naming the host's command.
- **`server install --ssh user@host`** (system `ssh`, the user's keys and `known_hosts`; an unknown host key refused): plans first, copies the verified release, runs there `setup --role server`, `server expose` and `server token` (LLM key on ssh stdin, token back in memory only), then `connect` here; never rolled back, the resume is the same command (0073 block 3, superseding 0024). Without ssh: `server install --print-commands`, no secret in any line.
- Client circuit breaker: 3 consecutive failures → no network for 5 min, writes to outboxes. TLS proxy and managed SSH tunnel: M7 (0073).

### 11.7 Updates [decided 0005 in principle; agent 0017, 0027]
- `jobs maintain` checks releases daily; `update check --json` returns versions and changelog entries since the installed one; the banner and doctor show "update x.y available" with the version only (release notes through `changelog`; they are unsigned). `changelog [--since v]` prints entries for humans and agents.
- `update apply`: download + minisign verification (current and next public keys embedded) → `<data>/bin/<v>/` → switch the shim → client migrations (numbered, idempotent, recorded) → regenerate plugin + `claude plugin update` → if the release pins a new digest, `server upgrade` run by the new binary (it owns its pin): lock → pull (a bad digest fails with nothing changed) → backup + verify → restore marker → up → health → smoke → unlock; any failure → previous digest + restore, shim switched back (0067 block 2 row in INDEX). Auto-apply opt-in. Digest bumps follow our cadence (CI: migration + recall parity on a fixture DB, E2 method), never upstream `latest`.

### 11.8 Backups [agent, 0023]
- `backup create`: lock (seconds) → `pg_dump -Fc` via `docker exec` → `pg_restore --list` check → `.tar.gz` with `manifest.json` (binary version, image digest, alembic revision, pgvector, embedding model + dims, bank ids, created_at), `db.dump`, `config.toml`, bank config, `compose.override.yaml`, client state; secrets included, the archive then **always `age`-encrypted** to the install's recipient (identity generated at setup, shown once with `backup identity show` to save elsewhere, or the user's own recipient such as an SSH key; `backup identity import` on another machine).
- `backup verify <file>`: decrypt, restore into a throwaway compose project, recall smoke, counts compared, removed. `restore <file>`: lock → stop → restore → start (a newer image migrates; an older image is refused) → verify → new restore epoch; every client (on a higher number, or another `restored_at` at any number, 0075) drops cursors newer than the backup and resumes from the server's document metadata (0044).
- `jobs maintain` runs backups by default: 7 daily + 4 weekly. Archives are the user's to copy anywhere.

### 11.9 Uninstall
`uninstall [--plan]`: plugin and marketplace, permission rule, scheduler entries, retention value (offered back, 0041), shim, PATH entry and binaries (last); config, secrets and state kept unless `--purge-local`, which keeps entries backsight did not write and first deletes this machine's `backsight:feedback:<machine_id>` control-bank document when it ever uploaded one (the joined server only, 5 s, never failing the uninstall; 0074 minors); then the server: keep (default), `--stop`, or `--delete-data` (typing the bank id; removes the volumes backsight's `compose.yaml` declares, never the user's override volumes). Backups are never deleted. Codex, where wired (0085): its plugins and marketplace (`codex plugin remove`, `codex plugin marketplace remove`), backsight's `[hooks.state]` tables through the config editor, the empty `plugins/cache/backsight/`, Codex's memories turned on again when backsight turned them off; `client uninstall --codex [--codex-home D] [--plan]` does that alone and forgets the recorded home, whose rollouts are then neither read nor sent from the backfill queue (`client uninstall` without `--codex` is refused: `uninstall` removes both).

## 13. Privacy and secrets [agent]

- **Redaction** before any write (session retain, subagent text, `memory_store`): private keys, known token prefixes (`sk-`, `sk-ant-`, `ghp_`, `github_pat_`, `xox?-`, `AKIA`, JWTs…), bearer headers, passwords in URLs, `KEY=secret` lines, high-entropy strings next to secret-like keys → `[redacted:<kind>]`. A corpus test is a release gate. `memory scan` re-checks stored memories and proposes `forget`.
- **Threats** (0046): leaked secret → redaction, `memory scan`, `forget --purge` (memory, source facts and document, for a session's document every part of it too, each tombstoned, with the parts that may still land, which the look for recreated documents purges when they land: never held by the queue, 0090; older backups still hold it, listed); poisoning by summarised hostile content → tool results never retained, recalled text framed as data to verify, `global` hits injected only above `recall.global_min_score`; never ask for keys in chat (guide).
- **Opt-out**: headless sessions never (`privacy.skip_entrypoints`, 0071); per project (`privacy.exclude_paths` in config, written by `pause --project`; a committed `.backsight.toml` with `retain = false` also works), per session (`pause` / skill `/<plugin>:pause` → flag read by writers; `resume` clears it).
- **Consent** at setup: a disclosure step (what is stored, where, which LLM provider sees transcripts, data-flow per provider lane) that needs an explicit yes (`--answer consent=yes` for agents, after showing it to the user); first-session notice (§6.2).
- Server: loopback by default, API and UI keys always set; secrets only in `secrets.toml` and the rendered `.env` (both 0600); backups with secrets always encrypted.

## 21. Glossary

- **Observation**: Hindsight's consolidated, deduplicated memory built from raw facts (`world`, `experience`) of the same scope.
- **Scope (observation)**: the tag set grouping facts into one observation pool; here one pool per project.
- **Transverse**: pseudo-project of sessions outside any repository; holds user-wide knowledge.
- **MIN_GAP**: prompts between two recall injections unless the topic clearly changed (3).
- **Sticky muting**: a memory injected 3 times within 24 h is muted unless its score is ≥ 0.97.
- **Entity index**: entity name → projects where it appears; rebuilt lazily (> 24 h old) through the API; feeds the nudge and the `related` scope.
- **Credited**: a reply containing the exact credit line; telemetry also counts free mentions, explicit empty results and silence (C12).
- **Outbox**: write-ahead file of notes and subagent reports not yet accepted by the server.
- **Settled session**: a session that ended, or whose last turn is ≥ 30 min old; its unsent turns are then retained in one pass.

### A.4 Telemetry event (one JSON per line)
Common: `ts`, `v` (instruction-set version), `event`, `session`, `project`, `binary_version`, `client` (0085: `claude-code`, `codex`; absent = `claude-code`; the journal's lines carry it too). Events and extra fields:
- `prompt`: `n`, `decision` (`recall|skip`), `reason` (`machine|too_short|same_topic|gap|budget|topic_shift`; `subagent`, 0085: a Codex subagent's task), `plen`, `scopes{name:{ok,ms,raw}}`, `above`, `injected`, `ids[]`, `top`, `ms`, `nudged`, `hinted`, `detector` (`rule|approval|null`), `chars`, `empty` (`no_candidates|below_floor|all_seen|capped|error`, when a recall injects nothing: no raw hit in any scope, none above the floor, all seen or muted, the hit limit or character room took none, or every scope failed (`error`, backsight PR 202); 0079 block 2).
- `outcome` (previous prompt's injection): `n`, `ids[]`, `searched`, `credited` (`exact|free|empty|null`), `credit_source` (`tool`: a `memory_credit` call of the main agent in that turn; else `citation`: a credit found in the reply; else absent, 0074), `contradicted` (the detector's rule/correction pattern fired on the next prompt).
- `briefing`: `ids[]`, `chars`, `source` (`observations|raw|empty`); `briefing_outcome`: `used_ids[]` at session end; `briefing_page_error`: `error` (the project's page could not be created).
- `tool`: `name`, `ms`, `hits`, `ok`; `result_chars` (all memory tools), and for `memory_search` `queries_n` and `query_hits` (per query, the hits returned that its answers held) (0083 C8).
- `stop_block` (0083 C8): once per end-of-turn block, when the blocked turn ends again: `outcome` (`used|confirmed|corrected|none|refused`), `paths[]` shown when it blocked (the briefing page left out), `shown`, `subagent`.
- `subagent_report_skipped` (0083 C3): a report the gate kept out: `length` (a bucket, e.g. `<50`), `agent_type`, `at` (`flush` when the outbox dropped it; absent at SubagentStop). Never the text.
- `subagent_sweep` (0083 C3): `gate`, `checked`, `purged`, `facts`, `unread`, `changed`, `status` (`done|failed|skipped`), `reason`.
- `briefing_trigger` (0083 C2): `job` (`tick|maintain`), `checked`, `patched`, `failed`, `gone`, or `error`; none for a bank without pages.
- `credit` (each `memory_credit` call, 0074): `verdict` (`used|none|wrong|outdated|invalid`), `ids_n`, `ok`.
- `credit_check` (each end-of-turn check of a turn that showed memories, §9.3): `outcome` (`declared|blocked|undeclared|check_skipped`), `shown`, `flags[]`, `after_block`.
- `retire` (each retirement answer, 0074 block 2): `action` (`retired|partly|hidden|sources`), `ids_n`; an answer that invalidated and hid emits a `retired` or `partly` event and a `hidden` one; a refused verdict, or one whose first PATCH the server refuses, emits none (`credit` counts the refusal).
- `feedback_error`: `reason` (`journal_write|turn_pointer|settle|shared_combine|ledger_missing|ledger_busy|ledger_unreadable|ledger_schema|ledger_json|ledger_export|ledger_fold`, the last seven from 0079 block 7), an enum, never error text (0079 block 2).
- `feedback_settle` (each settle in `jobs tick`): `shows`, `credits`, `misses`, `unknown`, `late` (used credits that found no unsettled show).
- `gate`: `n`, `decision` (`deny|allow`), `reason`.
- `retain`: `document`, `items`, `status` (`ok|queued|retry|quarantined|failed`), `ms`. A subagent's report is `queued` by the hook when it enters the notes outbox, then `ok`, `retry` or `quarantined` by the flush that sends it (0079 block 2; earlier versions logged nothing after `queued`, and the metrics then let the outbox decide what still waits).
- `store` (each `memory_store` or `backsight store`, 0079 block 2): `result` (`saved|updated|refused`: refused by the checks, the pause rule or the server's quarantine; updated when the note replaces memories), `kind` (empty when refused before parsing).
- `replace_unconfirmed` (0075): `session`, `document`, `reason`: a segment 1 this PC sent, given up 24 h after the send without being confirmed on the server.
- `server_start` (0073 block 1): `result`: SessionStart's late-address look spawned `server start` (and why), or failed to.
- `hook_failure`: `hook`, `kind` (`panic|fatal|timeout|invalid_output`), `ms`.
- `dashboard` (0079 block 4): `action` (`start|stop`), `ms` (start: time to listen; stop: run time), `pages` (pages served under a session; 0 at start). No link, code, port or path.
- `config` (0079 block 6): once a day from `jobs tick`, the numeric settings flat (`recall.<key>`, `feedback.<key>`) and `sha256` of them; no text setting. The Releases view marks a change of `sha256`.
- `job`: `name`, `status`, `ms`, `details` (`jobs tick`'s include `history`, the import of earlier history, 0074 block 3; `shared_up`, `shared_machines`, `shared_skipped`, `shared_error`, the shared ledger, block 4).
